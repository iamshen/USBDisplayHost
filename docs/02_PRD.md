# USB Display 上位机｜PRD

版本：v0.5 WPF UI 展示层设计基线　日期：2026-10-07

## 1. 产品目标与范围

让用户在 Windows 原生桌面程序中完成“连接设备 → 选择内容 → 显示主题 → 调整设备 → 切回副屏”，并能理解当前连接与操作结果。

正式首版 V1 支持一台选定设备、图片／时钟／基础仪表盘、主题态／副屏态切换、亮度、方向、纯熄屏、托盘、自启、配置、诊断和软件更新。内部 V0 先完成主题链路。后续候选以 [需求分析](01_需求分析.md) 为准。

界面采用 WPF/XAML＋WPF UI，统一窗口、导航、设置控件、对话框和提示；首版使用浅色主题并适配系统高对比度。设备功能按已确认的固件能力开放。页面骨架、视觉令牌、DPI 和可访问性要求见 [UI 设计规范](06_UI设计规范.md)。

## 2. 页面结构

| 页面／入口 | 主要内容 | 主要动作 |
|---|---|---|
| 设备首页 | 设备名称、连接状态、当前模式、当前主题、预览、必要错误 | 选择设备、连接／重试、切换模式、熄屏／唤醒 |
| 主题 | 图片／时钟／仪表盘三个模板；内容参数；预览 | 选择图片、修改内容、应用 |
| 设备设置 | 亮度、方向、帧率、画质、固件信息 | 即时调整亮度；应用方向／传输设置；恢复待应用字段默认值 |
| 应用设置 | 关闭窗口行为、自启、启动切换、退出策略、软件更新 | 保存设置、检查更新、下载、重启并安装 |
| 诊断 | 版本、驱动、最近错误、传输统计、设备反馈 | 导出诊断、打开日志目录 |
| 托盘菜单 | 当前设备与模式、运行状态 | 打开窗口、切换模式、暂停／恢复主题、退出 |

首启无设备时显示“未连接设备”和“重新检测”。不显示伪造预览状态、不报“发送成功”。无设备仍可编辑主题并保存草稿。

普通界面显示状态、必要信息和动作。VID/PID、端点号、报告编号等技术信息放入诊断页。错误示例：“设备连接中断，请检查 USB 连接。错误编号：USB-002。”

## 3. 状态与交互约束

| 状态 | 页面反馈 | 可执行动作 |
|---|---|---|
| 未连接 | 未连接设备 | 编辑主题、重新检测 |
| 正在连接 | 正在读取设备信息 | 取消连接、查看诊断 |
| 主题就绪 | 主题模式；显示运行／暂停状态 | 应用主题、设置、熄屏、切副屏 |
| 副屏就绪 | 副屏模式 | HID 支持的查询／控制、切主题 |
| 正在切换 | 目标模式与进行中反馈 | 查看诊断；重复切换按钮禁用 |
| 已熄屏 | 保留当前模式，另示已熄屏 | 唤醒、切模式；不自动套用亮屏协商 |
| 正在恢复 | 正在重新连接 | 查看诊断、停止恢复 |
| 不兼容／故障 | 原因和可执行动作 | 重新检测、导出诊断 |

“正在发送”只表示主机推流。“设备已显示”必须有可用设备反馈；预览是主机生成内容，不是设备截图。

## 4. 核心用户流程

### 4.1 首次使用

1. 安装应用及匹配的驱动组件，首次打开显示设备首页。
2. 自动发现已知设备；多台接入时让用户选定一台。
3. 校验身份、驱动、模式和能力。不兼容时显示原因并禁止推帧。
4. 如果设备处于副屏态，默认保留模式；用户点击“切换到主题模式”后再切换。
5. 主题态就绪后选择模板、预览并点击“应用”。应用结果与配置保存分别显示。

驱动安装属于安装流程。普通用户不需要用开发工具替换设备驱动。

### 4.2 编辑与应用主题

选择内置模板 → 编辑内容 → 查看草稿预览 → 应用到选定设备。点击应用前只更改草稿；准备合法首帧，在完整帧边界启用候选主题，首帧 USB 写入完成后保存恢复配置。传输完成、本地保存和设备呈现分别报告；没有呈现反馈时不显示“设备已显示”。

无设备、副屏态、暂停或熄屏时按钮显示“保存草稿”，不改变最近已应用配置；同会话暂停／唤醒后恢复当前活动配置；重连或重启恢复最近保存的配置，均不自动应用草稿。编辑下一份草稿不影响正在运行的主题，也不改变已经受理的应用操作。

应用失败保留草稿和旧恢复配置；首帧部分写入或结果未知时停流并恢复通信，不能宣称旧画面已还原。已发送但本地保存失败时显示“已发送，保存失败”，当前会话可继续新主题，重连恢复旧配置；提供仅执行本地写入的“重试保存”。本地保存成功不能单独证明设备显示成功。

图片支持 PNG/JPEG，适配模式为“完整显示”或“填充裁剪”。透明区域合成背景色后编码。模板使用白名单字段；不加载外部脚本或任意 XAML。

### 4.2.1 调整设备设置

亮度为即时控制，拖动合并尚未发送的目标值，释放或数值确认时提交最终值；区分请求值、读回值和待确认状态，确认后保存亮度意图。方向、帧率和画质通过“应用”生效，遵循与主题相同的候选首帧和持久化流程。恢复默认只修改待应用字段；即时亮度通过独立“设为 80”动作调整，不随恢复默认直接写设备。

### 4.3 模式切换

点击目标模式 → 应用停止冲突操作 → 发送控制 → 等待重枚举和目标态就绪 → 更新首页。

首次从副屏切出前说明 Windows 可能重新排列扩展屏上的窗口，允许不再提示。切换期间显示进度状态，不伪造百分比。

正常驱动已安装环境的等待目标为 8 秒。超时后先确认设备真实状态；发现目标态已就绪则完成，否则显示“切换未完成”或“设备状态待确认”。不直接改回原态、不连续自动重发命令。

### 4.4 关闭窗口与退出

关闭窗口默认收至托盘，首次提示一次；托盘继续运行主题。退出默认停止推流并释放设备，屏幕预期保持末帧，具体表现纳入样机验收。

同一用户会话重复启动时显示已有窗口，不另开设备会话。应用设置中未保存的编辑在显式退出时提供保存／放弃／取消；主题草稿独立保存，不因退出自动应用。系统关机不弹出阻塞确认。

可配置“退出时切回副屏”，仅在切换能力可用时显示。若切换超时，窗口保留结果提示，由用户选择继续退出或重试；系统关机使用有界清理，不阻塞系统退出。不发送会触发复位的 POWERDOWN。

### 4.5 软件更新

入口为“应用设置 → 软件更新”，展示当前应用版本、最近检查结果、可用新版本、更新说明和下载大小。软件更新不包含驱动和设备固件。

1. 用户随时可点击“检查更新”。后台检查默认开启，可关闭；主窗口或托盘初始化后异步检查，距上次自动尝试不足 24 小时则跳过，长期开启时最多每 24 小时一次。手动检查不受该间隔限制，同一时刻只执行一次检查／下载。
2. 有兼容的新稳定版时显示“发现新版本”，提供“下载更新”和“稍后”。仅检查不下载；无新版本显示“已是最新版本”，断网或超时显示“检查失败”，不能混为同一结果。后台检查失败仅在更新区域记录，不中断当前工作。
3. 用户点击下载后显示实际字节进度，可取消；没有总长度时使用不定进度。网络中断、空间不足或校验失败保留当前安装，允许重试。下载期间设备推流和页面操作继续运行。
4. 完整包校验通过后显示“已下载，待安装”，提供“重启并安装”和“稍后”。选择稍后、关闭窗口、普通退出或再次启动均不自动安装，也不强制升级。
5. 点击“重启并安装”后提示会短暂停止主题推流；保存主题草稿和必要配置，未保存应用设置先处理保存／放弃／取消。模式切换、恢复或其他设备写操作尚未收敛时禁止交接安装；失败则留在当前版本并说明原因。
6. 设备与文件资源完成清理后启动更新程序，退出主程序，安装成功再启动。安装重启不执行“退出时切回副屏”或“启动自动切主题”；新版本重新发现真实模式，按已保存配置及电源意图恢复可恢复的工作。应用更新不应主动引发模式切换或 USB 复位。

新进程确认当前版本已达到目标、配置可读且主窗口／托盘初始化成功后，才显示“已更新”。USB 设备未连接不算软件更新失败。下载完成不等于安装成功；安装或新版本启动失败时提供官方完整安装包修复路径和日志位置，不承诺未经验证的自动回滚。升级保留素材、草稿和设备配置，配置迁移前保留兼容备份。

## 5. 功能与验收

FR 编号与 REQ 编号一一对应；测试编号见 [项目规范](05_项目规范.md)。

| ID | 功能规则 | 验收标准 |
|---|---|---|
| FR-01 | 识别并选择设备；重枚举关联同一物理设备 | 两台同型号接入不串控；拔出选定设备不转而控制另一台（TC-01、TC-02） |
| FR-02 | 验证分辨率、协议版本和能力 | 描述符冲突或能力未知时不发扩展命令；显示不兼容原因（TC-03、TC-04） |
| FR-03 | 完整协商后发送 JPEG，超限拒绝或有界降质 | 分片边界与最大帧通过测试；屏幕测试图完整；USB 完成和设备呈现分开统计（TC-05～TC-08） |
| FR-04 | 三个内置模板，共用内容模型生成预览和设备图 | 草稿与活动预览分开；最小化仍运行；中文、图片、时间、指标一致；旧修订不覆盖新主题（TC-09、TC-29、TC-32） |
| FR-05 | PC 指标 1Hz 采样；设备指标按反馈更新 | 拒绝权限或传感器缺失显示“不可用”；超过 3 秒未更新标“数据已过期”，不显示假 0（TC-10） |
| FR-06 | 亮度 0～100；方向 0/90/180/270；刷新 1～5fps；质量 70～85 | 所有边界校验；亮度区分请求值和读回值；旋转后输出物理尺寸仍正确（TC-11、TC-12） |
| FR-07 | 托盘、默认关闭的自启、单实例及明确退出策略 | 关闭窗口与退出不同；重复启动不争用设备；自启可撤销；退出无后台残留发送（TC-13、TC-33） |
| FR-08 | 每设备保存已应用配置，草稿单独处理 | 损坏配置可恢复；未应用草稿不在重连后生效；发送与保存失败可分别恢复（TC-14、TC-31） |
| FR-09 | 热拔插、休眠、进程重启及失败恢复 | 不使用旧句柄，不从失败分片续传；恢复失败停止自动尝试（TC-15～TC-18） |
| FR-10 | 本地日志、错误编号、诊断包 | 能定位会话和操作；导出不包含用户图片或内存转储；日志有限额（TC-19） |
| FR-11 | 两方向 HID 切换，目标态就绪才报完成 | 超时、ACK 丢失与目标晚到均显示真实状态，不虚报回滚（TC-20、TC-21） |
| FR-12 | 两态 HID 通信；操作有确认或明确未知状态 | 非法报告不改变状态；重枚举重新打开 HID；旧 ACK 不完成新操作（TC-22） |
| FR-13 | 支持纯熄屏、唤醒；保持模式和配置 | 熄屏无 USB 复位；恢复连接不意外亮屏；不支持时禁用并解释（TC-23） |
| FR-14 | 离线安装、升级、卸载；日常普通用户运行 | 干净机运行；驱动失败可诊断；升级保留配置；卸载不擅自删除共享驱动（TC-24、TC-25） |
| FR-15 | 后续：触摸、镜像、动画、主题编辑器 | V1 不显示未交付入口；单独需求及验收后实施 |
| FR-16 | 后续：OTA、多设备并行、型号扩展 | V1 不试发相关命令；单独版本规划 |
| FR-17 | 手动／后台检查、下载、确认安装、版本反馈和失败恢复 | 检查失败不报最新版；稍后不暗中安装；安装前收敛设备操作；升级保留配置与素材；离线核心功能正常（TC-34～TC-38） |

FR-06 的副屏态亮度和熄屏依赖冻结后的 HID 能力矩阵。若正式协议仅在主题态支持，页面必须限制适用模式，并在 V1 范围评审中明确，不能通过未验证路径控制副屏驱动。

## 6. 默认值

这些值是本次产品设计，非设备固有参数。实现与测试统一使用本表。

| 项目 | 默认 |
|---|---|
| 首选模式 | 保持设备当前模式；首次使用不自动切主题 |
| 启动自动切主题 | 关闭，用户显式启用后生效 |
| 关闭窗口 | 收至托盘 |
| 开机自启 | 关闭 |
| 退出 | 停止推流并释放接口；不自动切换 |
| 内容 | 图片模板；未选择图片时使用内置测试背景 |
| 静态内容刷新 | 内容变化时发送；无变化不为“保活”重复推图 |
| 时钟／指标采样 | 1Hz；渲染上限默认 5fps |
| JPEG 质量 | 80；超限依次尝试 75、70 后停止 |
| 亮度 | 优先读回设备值；无法读取且首次协商必需时使用 80 |
| 方向／适配 | 0°／完整显示 |
| 设备状态查询 | 1 秒一次；无有效更新 3 秒标为过期 |
| 自动恢复 | 每次故障最多 1 个恢复周期，失败等待用户或新插入事件 |
| 日志 | 本地；单文件 10MiB，最多 5 个文件；不外发 |
| 管理界面 | 浅色主题；支持系统高对比度；启动进入设备页 |
| 时钟模板 | 24 小时，显示日期；日期采用本机区域格式 |
| 自动检查更新 | 开启，可关闭；每次自动尝试间隔至少 24 小时，手动检查不受限 |
| 下载／安装更新 | 均由用户发起；稳定版通道；不强制更新、不自动降级 |

## 7. 非功能目标

测试前记录 PC、Windows build、USB 拓扑、固件、驱动、测试主题和构建版本。以下不是已实现指标。

| ID | 目标 | 测量与准入 |
|---|---|---|
| NFR-01 | 1080×2400、5fps 基础显示 | 100 帧编号测试图；核验屏幕和设备错误计数，无协议错位／花屏 |
| NFR-02 | 切换 P95≤8 秒 | 驱动已装环境双方向各 50 次；从受理到目标可操作；首次安装另测 |
| NFR-03 | 操作受理反馈≤200ms | 普通页面操作与硬件进行中状态，不等同硬件完成 |
| NFR-04 | 内容生成至 USB 完成 P95≤1 秒 | 5fps 固定主题；设备呈现延迟单列，无回传时标无法测量 |
| NFR-05 | 连续运行 24 小时稳定 | 无崩溃、死锁、无限重试；内存与句柄不持续增长 |
| NFR-06 | 合理资源占用 | 初始预算平均 CPU≤5%、工作集≤300MiB；G0 以固定参考机实验后冻结 |
| NFR-07 | 系统恢复稳定 | 50 次拔插、20 次休眠唤醒；无串认设备和旧会话污染 |
| NFR-08 | 有界资源和输入处理 | 一个在途帧＋一个待发最新帧；异常图片、配置及日志不导致无限增长 |
| NFR-09 | 普通用户可完成核心操作 | 不为界面和推流强制管理员；可选温度采集失败不影响显示 |
| NFR-10 | 状态可信 | 不将 USB 完成当作呈现，不将请求亮度当作实际值，不把超时当回滚成功 |
| NFR-11 | 原生界面可读可操作 | 640×400 DIP 紧凑客户区、100%～200% DPI、混合 DPI、系统文字放大、全键盘、读屏器及高对比度通过 TC-29、TC-30 |

主机主动丢弃尚未发送的旧帧属于保持最新内容的策略，单独计数；不能用该计数掩盖设备协议丢帧。

## 8. 发布条件

V0：主题态出图、协议边界、恢复、配置、原生 UI 和真实屏幕验收通过；标注内部验证用途。

V1：V0 条件加上 HID 协议、双向切换、纯熄屏、驱动安装、普通用户运行、软件检查与安装更新、升级卸载与长稳证据全部通过。纯熄屏或双模未完成时只能交付 V0，不能通过隐藏按钮宣称 V1 完成。

签名、驱动授权与受支持 OS 列表随正式安装包交付。未经验证的能力不进入功能介绍。

# USB Display 上位机｜产品需求文档（PRD）

版本：v0.1 评审稿　日期：2026-10-06　工程名：UsbDisplayHost（暂定）

## 1. 文档说明

需求来源为 S1《USB_副屏协议与局部刷新原理.md》和 S2《上位机实现文档.md》。协议事实与已知冲突见《01_需求分析》。**本 PRD 中的版本切分、默认配置、交互规则及新增验收阈值是建议基线；不是用户已经确认的商业承诺，也不是已经完成的功能。**

范围：Windows PC 上位机；AD100 / VTDR6115 1080×2400；主题态与 Windows 副屏态。首版建议 Windows 11 x64，单次控制一台设备；多设备身份隔离必须正确，但不承诺并行推流。

## 2. 产品目标与发布定义

| 版本 | 产品结果 | 必备能力 |
|---|---|---|
| R0 内部主题版 | 能可靠显示静态主题和硬件仪表盘，能定位连接与推流错误 | FR-01～FR-10；已实现能力范围内运行 |
| R1 双模正式版 | 用户不接触协议或开发工具即可使用主题屏与原生副屏 | R0 + FR-11～FR-14；固件、驱动、安装与恢复共同验收 |
| R2 扩展版 | 逐项增加触摸、动态内容、镜像或文件下发 | FR-15 / FR-16 独立立项 |

不纳入 R0/R1：云端账号、既有业务系统集成、主题商城、任意脚本主题、所见即所得编辑器、跨平台宿主、自研 Windows 显示驱动、OTA、开机动画下载、上位机 rlx 编码、30/60fps 保证。

原生副屏不是“上位机抓屏再传图”。副屏态画面由厂商 Windows 显示驱动负责；桌面镜像是另一个可选的主题态内容源。[S2 §1.3、§2.1]

## 3. 用户旅程

### 3.1 首次使用

启动 → 检查依赖和设备 → 展示设备型号、模式与兼容状态 → 当前副屏态时提供“切为主题屏”入口 → 说明扩展屏窗口可能移动 → 用户确认 → 验证目标模式可用 → 展示主题列表与预览 → 应用。

未安装驱动、固件不兼容、仍为 CDC、无设备是四种不同状态，不得统一显示“连接失败”。R0 未具备 HID 切换能力时展示工程版本限制，不提供无效切换按钮。

### 3.2 日常使用

系统托盘启动 → 恢复设置 → 识别当前真实模式 → 根据已保存的启动策略处理 → 主题态按内容变化更新 → 设置窗口关闭后托盘继续运行。

默认不强制切换模式。用户可以明确启用“启动时切换到主题态”，但仍需当前固件支持且当前设备身份匹配。

### 3.3 切回副屏

用户选择切回 → 停止主题发送 → 发送 HID 绝对目标模式命令 → 等待目标设备和驱动就绪 → 验证显示拓扑中出现对应显示器 → 显示“副屏已就绪”。

切换导致扩展屏窗口重新布局是应提前说明的系统影响；保持最后一帧是固件目标，不承诺所有失败路径均无黑屏。[S2 §3.4～§3.6]

### 3.4 故障处理

提示具体状态 → 提供与原因相符的动作（重试连接、检查驱动、重新插拔、导出诊断）→ 后台执行有界恢复 → 以实际检测结果结束。不能仅将 UI 状态改成“已恢复”。

## 4. 信息架构与页面职责

| 页面/入口 | 必须包含 | 不应包含 |
|---|---|---|
| 设备与状态首页 | 设备身份、连接/模式/推流三个状态、固件/驱动兼容摘要、主要操作 | 大段原始 USB 十六进制、堆栈 |
| 主题 | 内置模板、预览、应用、适配方向、当前生效标记 | 任意代码运行、主题市场和复杂编辑器 |
| 监控 | PC 指标选择、来源、传感器绑定、可用性、更新时间 | 把 PC 温度与屏幕温度混为一类 |
| 设备设置 | 亮度、方向、目标帧率、JPEG 质量、启动/退出行为 | 在未知固件上直接发扩展命令 |
| 诊断 | 版本组合、连接过程、发送统计、错误摘要、导出 | 默认上传内容图像或完整序列号 |
| 托盘 | 当前状态、打开设置、切模式、暂停/恢复、退出 | 与主窗口不一致的另一套状态 |

管理界面统一使用 Fluent UI。颜色可沿用既有军蓝 `#003366`、中性灰和香槟金 `#C3AA78` 作为应用 token；这是管理 UI 建议，不限制屏幕主题内容的配色。设备屏物理比例为 1080:2400，即 9:20，不沿用商户 APP 的 9:16 画布。

## 5. 功能需求

### FR-01 设备发现与身份识别

**关联：**REQ-01；R0/P0；依据 S2 §2、§4.1。

设备列表显示型号、序列号脱敏值、USB 模式、连接状态与可操作能力。身份基于稳定序列号并结合接口用途进行匹配，PID 只是模式标志；接口路径、USB 地址和端点号不是长期身份。

首次接入时识别目标设备并读取描述符。出现第二台时不得随机操作第一台或错误继承另一台设置。首版允许切换选中的控制对象，不自动对所有设备推流。

**验收：**AC-01.1 启动前已插入和启动后插入均可发现；AC-01.2 同一设备换 PID 后仍归入同一设备；AC-01.3 不将 touch HID 识别为 vendor HID；AC-01.4 拔掉选中设备不会把设置应用到另一台。

### FR-02 能力与兼容性检查

**关联：**REQ-02；R0/P0；依据 S1 B7/B10/B13、S2 §6.6。

连接后校验硬件配置档、协议版本、分辨率、JPEG 上限、传输限额、可用模式和可用控制。未知能力默认不可用。只有基本 0xAF/EP0 的旧固件可使用经过白名单验证的兼容档，不推断其具备 HID、纯熄屏或 OTA。

设备宣告为 1920×1080 而物理配置档为 1080×2400 时，正常模式禁止推图，展示“设备分辨率声明与硬件配置不一致”。工程覆盖必须有明确警示，默认关闭，不进入量产设置。

**验收：**AC-02.1 不兼容固件不推送图像；AC-02.2 未实现功能隐藏或禁用并说明原因；AC-02.3 兼容报告记录实际原始描述符与匹配的配置档版本。

### FR-03 主题态出图与推流

**关联：**REQ-03；R0/P0；依据 S1 B4/B5、S2 §4.3。

按确认分辨率产生基线 JPEG，使用完整 `0x68…0x69` 协议记录。单帧上限按当前契约为 1 MiB；每次写入预算不超过 240 KiB，且必须计入头部并受设备/WinUSB 更小限额约束。协商必须执行到 `BLANK_MODE ON` 才进入发送。

单张静态图允许按需刷新；时钟在显示内容改变时更新；仪表盘默认最多 5fps，指标默认 1Hz 采样。最新完整待发帧替换旧待发帧，不能无界积压；正在发送的帧不允许拆开让后续新帧插队。

**验收：**AC-03.1 测试图尺寸与方向正确；AC-03.2 单片、多片和 1 MiB 边界正确；AC-03.3 超限在主机端拒绝或有界重编码，不能上传截断 JPEG；AC-03.4 暂停后不再发送图像；AC-03.5 USB 写完成不被描述为“设备已显示”。

### FR-04 主题与预览

**关联：**REQ-04；R0/P0；依据 S2 §5，模板范围为建议。

内置三个基础模板：静态图片、时钟、硬件仪表盘。用户可选择本地 JPEG/PNG 作为背景，选择内置布局和受控参数；不执行导入的 JavaScript、Razor、DLL 或外部链接。

预览与设备内容使用同一逻辑渲染模型；无设备也可预览。预览需要明确区分“本地预览”和“设备正在显示”；仅本地应用成功不能显示“已发送”。

图片导入校验格式、文件大小、像素解码预算和可解码性。候选限制为原文件不超过 20 MiB、解码不超过 16MP；这两个值需在 G0 参考机测试后冻结，避免压缩图片解码占用失控。

**验收：**AC-04.1 不接设备也能预览；AC-04.2 应用后的布局与预览一致；AC-04.3 损坏和超大图片有明确提示且不崩溃；AC-04.4 配置错误不污染上次可用主题。

### FR-05 硬件指标与数据质量

**关联：**REQ-05；R0/P0；依据 S2 §5.2。

PC CPU/GPU/风扇等来自 PC provider；屏幕温度、设备芯片温度和设备计数来自固件状态。每个指标至少有来源、稳定标识、类型、单位、值、采样时间、质量状态。

质量状态为有效、不可用、权限不足、读取失败、过期。无值不等于零。默认数据超过 3 个采样周期未更新即标为过期，保留最后值时必须标识“历史值”。

不得保证所有主板、显卡或风扇均支持读取。温度采集失败不影响壁纸、时钟与显示功能。用户拒绝可选采集权限后，应用仍可继续使用。

**验收：**AC-05.1 缺失显示“—/不可用”而非 0℃；AC-05.2 PC 与设备同名温度不混用；AC-05.3 传感器重新枚举后不会按列表下标绑定到另一项；AC-05.4 采集异常不阻塞推流与控制。

### FR-06 显示参数

**关联：**REQ-06；R0/P0；依据 S1 B4/B10、S2 §5.3。

亮度有效范围 0～100。对可查询参数分别展示“期望设置”和“设备报告值”；只有写入而没有确认时，状态为“已提交/未确认”，不假称成功。

方向支持 0/90/180/270 度，由上位机渲染实现。横屏排版使用换向逻辑画布，再映射到实际面板像素帧，不随意更改设备宣告尺寸。R0 不发送未实现的设备旋转指令。

首版目标帧率范围建议 1～5fps，静态按需可低于 1fps；默认 JPEG 质量 80，常规配置范围 70～85。过大帧允许有限次数降低质量，仍超限则拒绝该帧并提示，不擅自改变已协商的分辨率。

**验收：**AC-06.1 亮度越界不能提交；AC-06.2 四个方向均以测试图验证；AC-06.3 JPEG 超限不会产生无效数据；AC-06.4 调低帧率不会阻塞 HID 监听；AC-06.5 副屏态只有支持 HID 同类控制时才能调亮度。

### FR-07 托盘、启动与退出

**关联：**REQ-07；R0/P0；依据 S2 §3.3、§6.3。

关闭设置窗口默认最小化到托盘，并在首次操作说明。显式退出才终止进程。开机自启默认关闭，可由用户开启。

退出默认停止发送并保持最后一帧，不发送 `AF 20 1F 02`。R1 可提供“退出时切回副屏”选项，必须等待切换结果或明确提示未确认，不能静默认为已成功。

单设备只能被一个本机运行实例控制。第二实例应激活已有窗口，或提示另一会话占用；不可抢夺设备句柄。

**验收：**AC-07.1 关闭窗口后推流按配置继续；AC-07.2 退出后没有残留采集/发送任务；AC-07.3 不发送 POWERDOWN；AC-07.4 自启不产生多个控制实例。

### FR-08 配置保存与恢复

**关联：**REQ-08；R0/P0；依据 S2 §6.3，恢复规则为建议。

保存应用配置、每设备显示配置和主题配置。配置带 schemaVersion；写入采用临时文件、校验、原子替换并保留上一次可读配置。

UI 保存成功表示配置落盘成功，不代表某个硬件指令执行成功。设备断开时可保存期望设置，重新连接后经兼容性检查再应用。

**验收：**AC-08.1 重启恢复设置；AC-08.2 保存中断不会留下半份 JSON；AC-08.3 配置损坏能回退并提示；AC-08.4 未知 schema 不覆盖原文件；AC-08.5 不能把另一设备的当前模式当作持久化真值。

### FR-09 异常恢复与电源事件

**关联：**REQ-09；R0/P0；依据 S1 B8、S2 §3.7、§6.1。

USB 拔出立即停止新 I/O；超时、短写或不确定部分发送视为当前会话可能失去同步，不续发剩余片段。先终止在途操作，再按已确认复位契约清理、重建会话与协商，然后发送新完整帧。

恢复采用有界次数和退避，禁止无限重试。恢复期间 UI 显示“正在恢复”，不是“主题显示中”。休眠前释放或挂起会话；唤醒后重新发现设备，不使用旧路径/句柄。会话锁屏不自动切模式，镜像功能未来必须暂停敏感内容捕获；基础主题可按用户设置继续。

**验收：**AC-09.1 分片中途拔出不崩溃；AC-09.2 模式切换时旧 I/O 回调不会污染新会话；AC-09.3 休眠后可重新连接；AC-09.4 多次失败进入可理解的不可用状态，不反复重置设备。

### FR-10 日志、指标与诊断导出

**关联：**REQ-10；R0/P0；依据 S2 §6.2。

正常界面显示连接状态、发送帧率、目标帧率、异常摘要。诊断区可显示固件版本、驱动版本、协议配置档、原始描述符、编码耗时、帧大小、USB 耗时、短写/超时、模式切换各阶段耗时。

“设备 FPS”仅在固件字段语义已明确时显示；未回传时显示未知。保留 droppedBeforeSend（主机主动替换）和 transportFailure（传输失败）的区别。

日志默认本地保存，建议滚动文件总量不超过 100 MiB，并按 14 天保留策略取先到上限者。导出由用户主动触发，默认脱敏序列号、用户名路径，不包含壁纸、屏幕帧、内存转储或其他私人内容；包含这些内容需单独同意。

**验收：**AC-10.1 单次失败可通过 OperationId 串联；AC-10.2 无原生堆栈暴露给普通 UI；AC-10.3 无 HID 时不虚构设备呈现成功；AC-10.4 日志与诊断包有大小上限。

### FR-11 双模切换

**关联：**REQ-11；R1/P0；依据 S2 §3。

前置条件：固件声明支持模式切换、稳定身份和所需 HID；目标驱动已具备安装条件。命令使用绝对目标值（主题或副屏），不能用 toggle，以减少重复提交歧义。

切换中禁止第二次切换、主题应用和依赖旧模式的控制；允许查看进度与诊断。USB 重枚举后以同一设备身份重新绑定。主题态成功条件是 WinUSB 可用、协商完成且首帧 USB 传输成功；设备是否已呈现仍按是否具备反馈区分。副屏态成功条件包括对应显示器已进入 Windows 显示拓扑。

普通已装驱动场景沿用原文 8 秒目标；首次驱动准备单列“等待驱动”阶段，建议最多等待 60 秒后结束当前尝试并给出安装指导，而非每 8 秒重发切换命令。该延长值为建议，不改变源文的原始要求。

超时后先核实实际状态。只有 HID 仍可用、命令语义已确认且确有必要时，最多进行一次受控补偿；无法验证原态时显示“恢复未确认”，不显示“已回滚”。

**验收：**AC-11.1 两方向可用；AC-11.2 100 次循环无状态卡死与设备串认；AC-11.3 未就绪不会提前报成功；AC-11.4 重复点击只产生一个操作；AC-11.5 驱动缺失不靠反复切 PID 修复。

### FR-12 HID 状态、控制与回执

**关联：**REQ-12；R1/P0；依据 S2 §4.5、S1 附录 C。

显示 Input 状态与采样时间；通过 Feature/协议能力查询确认支持功能。Report ID、长度、版本、错误码、RequestId、ACK 阶段必须来自冻结的固件契约。

命令至少区分已提交、设备接受、设备执行完成、拒绝、超时、不支持。对于模式切换，收到“接受”不等于新模式已就绪。对于旧版无回执能力的命令，不虚构完成事件。

**验收：**AC-12.1 两态均可在接口存在时读取 vendor HID；AC-12.2 重枚举重新打开句柄；AC-12.3 无匹配请求的回执被记录但不改状态；AC-12.4 触摸和控制报告不会误解析。

### FR-13 纯熄屏与唤醒

**关联：**REQ-13；R1/P0；依据 S1 B13、S2 §6.6。

仅在纯熄屏能力已确认时开放。熄屏暂停不必要渲染和发送，保留控制链路。唤醒后恢复所选主题并推最新完整帧。亮度为零、暂停推流、纯熄屏、切回副屏是四个不同动作，UI 不混为“关闭”。

**验收：**AC-13.1 熄屏不会触发复位或换 PID；AC-13.2 唤醒后内容更新；AC-13.3 不支持时给出原因且不退化为 POWERDOWN。

### FR-14 安装、升级与权限

**关联：**REQ-14；R1/P0；对源文 §2.2 的工程扩展。

正式交付包含上位机、必要运行依赖、已核验的驱动获取或安装路径、兼容矩阵与版本清单。应用、驱动和固件版本分开显示，不把三者统称“软件版本”。

主程序以普通用户权限运行。驱动安装和确需权限的硬件采集使用独立且受限的授权步骤；拒绝授权不影响基础主题。不得要求关闭系统安全机制或使用测试签名模式作为正式安装条件。

首版采用人工触发、已签名安装包升级，不默认引入自动更新服务。升级保留用户配置与回退路径；卸载不默认移除其他设备共用的厂商驱动。Zadig 仅是研发工具。

**验收：**AC-14.1 干净 Windows 环境安装成功；AC-14.2 普通用户可运行基础功能；AC-14.3 离线安装按已声明依赖完成；AC-14.4 升级失败可恢复旧版；AC-14.5 签名和依赖清单可核验。

### FR-15 触摸（R2/P1）

副屏态使用 Windows 触摸通道并验证 Container ID 映射；主题态使用 vendor 坐标，由渲染变换的逆矩阵映射到逻辑内容。必须处理接触 ID、按下/移动/释放、坐标边界和切换时释放状态。

是否单点或多点、具体触摸 IC、report descriptor 及触摸在两态的启用规则由固件评审冻结。未冻结前仅输出验证计划，不提供看似可用的触摸配置。验收包括四方向、边角、黑边和多外接显示器场景。

### FR-16 后续能力（R2/P1–P2）

动态主题与镜像要单独做帧率、延迟和功耗预算。多设备并行需要总 USB 带宽和各设备隔离测试。OTA/动画文件下发必须另有认证、长度、分块、ACK、校验、恢复和断电策略；当前 `0x20` 一字节 val 与示意 `0x21` 不是完整文件传输协议。

本条为候选集合，不作为 R1 的隐含交付责任。

## 6. 状态模型与操作可用性

UI 显示由三部分组成：连接状态（未连接/检查中/就绪/不可用）、模式（主题/副屏/未知）、运行状态（推流/静态保持/暂停/切换/恢复）。不使用一个模糊的“在线”概括全部情况。

| 场景 | 应用主题 | 亮度 | 模式切换 | 诊断 | UI 主提示 |
|---|---|---|---|---|---|
| 无设备 | 仅预览 | 禁用 | 禁用 | 可导出本机信息 | 请连接设备 |
| 检查中 | 禁用 | 禁用 | 禁用 | 可查看 | 正在检查兼容性 |
| 主题就绪 | 可用 | 按能力 | 按能力 | 可用 | 主题显示 / 静态保持 |
| 副屏就绪 | 仅预览 | 仅支持 HID 时 | 按能力 | 可用 | Windows 副屏 |
| 切换中 | 禁用 | 禁用 | 禁用 | 可用 | 显示当前阶段，不显示伪百分比 |
| 恢复中 | 禁用 | 禁用 | 禁用 | 可用 | 正在恢复连接 |
| 不兼容/不可用 | 仅预览 | 禁用 | 仅经验证的恢复动作 | 可用 | 明确原因与下一步 |

示例错误提示：“未找到主题态驱动，请安装受支持的驱动包后重试。诊断编号：UDH-…”。原生错误码、调用栈和设备路径进入诊断详情，不进入默认 Toast。

## 7. 默认配置建议

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启动自动切主题 | 否 | 不擅自重排 Windows 桌面 |
| 开机自启 | 否 | 用户显式启用 |
| 关闭窗口 | 留在托盘 | 与退出分开 |
| 退出行为 | 保持最后一帧 | 非断电保图；不发 POWERDOWN |
| 主题帧率上限 | 5fps | 静态按需，不设置 JPEG 保活要求 |
| 指标采样 | 1Hz | 与渲染频率分离 |
| JPEG 质量 | 80 | 常规范围 70～85，超限有界降级 |
| 上位机 rlx | 关闭 | 保留固件副屏驱动自身所需 rlx |
| 方向 | 0° | 由主机渲染，不发送未实现旋转命令 |
| 亮度 | 优先保留设备值；未知时建议 80 | 区别于原文协商示例的 100 |
| 遥测外发 | 关闭 | 诊断默认本地 |
| 传感器提升权限 | 不自动请求 | 用户启用相关功能时说明与授权 |

## 8. 非功能要求与验收方法

以下为新增建议目标。G0 必须登记参考 PC、Windows build、USB 控制器/Hub/线材、固件/驱动版本与主题素材；条件未冻结时只采集结果，不声称已达到通用性能。

| ID | 目标 | 方法与成功定义 |
|---|---|---|
| NFR-01 | 1080×2400，5fps 基础档 | 动态测试图连续 100 帧无协议错位；按设备诊断或外部观测核验，不仅统计写成功 |
| NFR-02 | 正常已装驱动切换 95%≤8s | 两方向各取样，记录从发命令到目标 operational；首次安装单列 |
| NFR-03 | UI 操作反馈≤200ms | 测用户动作到“已受理/进行中”，不把硬件执行时间算成即时完成 |
| NFR-04 | 新快照到 USB 完成 P95≤1s | 5fps 参考场景；指标采样延迟和实际 LCD 呈现另列 |
| NFR-05 | 24h 连续主题运行稳定 | 无崩溃、无无限重试、无持续内存增长；定期采样进程树与 native 内存 |
| NFR-06 | 资源预算可控 | 候选上限：参考机平均总 CPU≤5%，进程树内存≤512MiB；G0 测量后冻结或经评审调整 |
| NFR-07 | 100 次模式往返、50 次休眠恢复 | 无死锁、串认设备、旧句柄污染；失败都有明确状态及证据 |
| NFR-08 | 队列与日志有界 | 帧队列 1～2；日志总量与保留时长按策略截断；所有丢弃均有分类 |
| NFR-09 | 最小权限与输入安全 | 标准用户、拒绝授权、损坏图像、恶意配置、路径穿越等测试通过 |
| NFR-10 | 可观测性真实 | USB 完成、解码、呈现三种口径不混淆；无法观测的指标标为未知 |

“零丢帧”只用于约定测试负载中的设备异常丢帧；主机为保持最新主动替换未发送帧属于设计行为，必须单独记录，不能算成协议失败或被隐藏。

## 9. 发布验收准入

R0 必须有主题态协议基线、边界封包用例、真实屏幕图像验证、5fps 基础测试、拔插恢复与配置恢复证据。R0 不允许标记为“双模正式版”。

R1 还必须有 HID 能力与 ACK 契约、双向切换测试、纯熄屏不复位验证、干净机驱动安装、普通用户运行、签名安装包、兼容矩阵和售后诊断流程。所有影响数据同步、设备错误控制或状态虚报的 P0 问题必须关闭。

需求变更需同步更新 REQ、FR、测试 AC/TC、任务与协议版本；尤其是触摸、OTA 和多设备并行，不得通过“顺便增加一个入口”进入首版范围。

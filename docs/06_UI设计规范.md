# USB Display 上位机｜UI 设计规范

版本：v1.5 原生设备工作区　文档更新：2026-10-22

## 1. 设计目标

采用 WPF/XAML＋WPF UI 的原生桌面工具。设备状态、内容预览和当前操作构成页面主线；深炭灰画布、对齐、分组留白和少量蓝色主要操作构成视觉层级。普通字段组直接排列在画布上，不以卡片、边框或背景重复分组。FluentWindow＋TitleBar 保留 Windows 窗口操作。

产品行为以 [PRD](02_PRD.md) 为准，状态与线程规则以 [软件技术架构](03_软件技术架构.md) 为准。当前实现与验证边界见 [界面精简记录](verification/ui-simplification-2026-10-22.md)，历史窗口及 DPI 证据见 [UI 完善记录](verification/ui-polish-2026-10-15.md) 和 [全页面重排记录](verification/all-pages-redesign-2026-10-13.md)。设计目录中的 SVG／PNG 是静态设计资产，不能代替实际 WPF 截图。

页面优先回答当前任务需要的信息：设备页确认设备与可用动作，主题页编辑并预览内容，设置页调整参数，诊断页定位问题。字段名称、范围、反馈来源、不可用原因和恢复入口必须保留；重复上下文、装饰图标及解释控件本身的文字不常驻。次要过程放入详情，错误不因折叠而隐藏。

默认深色，系统高对比度优先。设备主题背景色只改变设备内容。共享字体、语义画刷、面板、分隔线、反馈和焦点样式集中在 ResourceDictionary；页面沿用原生控件、绑定和命令。

## 2. 信息架构与窗口骨架

固定设备、主题、设备设置、诊断、应用设置五个入口。导航由图标、中文名称、选中底色和指示线共同表达位置。顶部导航默认启用；侧边导航宽 184 DIP，采用横排图标和文字。小于 800 DIP 时收为不透明的页面菜单，选择后收起。两种布局共用五个页面实例和一个内容宿主。

800～999 DIP 的顶部导航将诊断与应用设置收入更多菜单。按钮显示当前所在的折叠页面名称，可访问名称始终包含当前页；菜单以勾选标记定位当前页，重复点击当前页不取消其标记，其他主要导航不保留旧选中。

设备选择影响所有页面。选择候选与连接分别执行；切换设备先收敛旧操作并释放旧会话。切页、切换导航布局和预览主题均不自动发送设备命令。

| 区域 | 内容 |
|---|---|
| 标题栏与导航 | 产品名、五页定位、设备选择或未连接状态 |
| 页头 | 页面名称；必要的连接状态或页面动作 |
| 主体 | 预览、紧凑字段组或日志列表，按任务组织 |
| 页内反馈 | 持久错误和操作结果；空反馈不占行 |
| 编辑页底栏 | 状态、恢复默认／撤销、一个主要操作；独立布局行，不覆盖字段 |

主题和设备设置不提供草稿归属、读写或管理入口。主题可离线编辑预览；连接且满足状态条件时显式应用，成功后自动保存设备恢复配置。应用设置保留显式“保存设置”。本地配置、活动内容和设备实际反馈在内部保持区分。

## 3. 设备页

未连接时显示简短连接说明和“先预览主题”，使用留白区分连接引导与可用设备列表。重新检测位于页头，不重复出现；无候选时隐藏选择／连接按钮。可用设备列表与连接详情分开。

已选择设备时，左侧展示名称、分辨率和 16:9 主机画面预览；右侧展示连接、模式、电源、播放状态及控制，两个区域以间距区分，不加外层卡片。模式操作使用明确按钮，不能用立即选中的控件暗示设备已切换。暂停／恢复、熄屏／唤醒按真实状态互斥显示。

固件、生命周期及协议过程放入“连接详情”；持续错误与对应恢复入口留在详情之外。重试预览只在预览失败时显示。副屏态不伪造桌面镜像；主机预览与设备呈现反馈独立。

## 4. 主题页

页头显示当前会话设备标识，完整内容可通过提示及辅助技术读取，不使用顶部候选设备冒充当前设备。宽屏左侧为大幅真实预览及下方图片、时钟、仪表盘三个等宽缩略图选项，右侧约 320 DIP 以细分隔线区分参数，直接排列当前模板标题和字段，图片适配与颜色使用相同的标签／控件列；主体不足 780 DIP 时参数区堆叠到预览与选项下方。模板用蓝色边框、名称及勾选共同表达选中状态。预览下保留一条“本地预览 · 应用后发送到设备”，不另设重复标题。预览保持物理比例，窄窗口限制高度，主体可滚动。

| 模板 | 可编辑内容 |
|---|---|
| 图片 | PNG／JPEG、完整显示／填充裁剪、背景色；未选图时使用内置屏幕标识 |
| 时钟 | 24 小时制、显示日期、背景色和文字色 |
| 仪表盘 | CPU、内存、主机／设备温度项以两列排列，另有背景色和文字色；无来源时显示不可用 |

颜色保留常驻标签，紧凑折叠入口显示当前色块、HEX 值及展开标记；展开后保留等宽十六进制输入和原六色色板。非法输入不覆盖原文，色块留空，持续校验错误显示在折叠区外。色板保留名称、色值提示、焦点和选中勾选，展开入口可通过键盘操作并暴露展开状态。模板选项沿用 ListBox 单选语义，支持方向键、Home／End 与焦点移动；选中模板缩略图复用通过修订归属检查的当前离屏位图；图片缩略图仅在素材、适配、背景一致时复用最近位图，编辑或恢复后不匹配则清除。时钟和遥测不缓存到其他模板，未选中的时钟／仪表盘使用布局示意，不将示例数据冒充实时数据。主预览仍由同源离屏渲染结果生成，不能用静态截图替代交互控件。

设备内容中，时钟使用粗体小时／分钟，秒和上下午标记为次要层级；可选日期沿用本机区域的完整日期，并在区域格式未包含星期时补充星期，整体按实际文字高度居中。仪表盘使用居中标签、粗体数值和基线对齐的单位，指标之间仅保留细分隔线；四项时为 2×2，其余按选中数量和逻辑横竖比例排布。数值下保留数据来源，无有效来源显示“不可用”，过期数据保留明确文字提示。次级文字与分隔线由用户指定前景／背景色混合生成，不改变所选配色或采样语义，不绘制虚构趋势。上述排版由共享离屏渲染生成，主预览与设备内容保持一致。

页头随主体一起滚动。编辑视口高度不足 280 DIP 时，预览高度限制为 112～140 DIP，来源说明保持可见并随预览滚动；不拉伸设备画面。普通高度按主预览与下方三张缩略图的比例分配空间，扣除页头、来源说明及间距，宽屏／堆叠预览上限仍为 360／240 DIP；主预览外框与真实画面保持同一比例。高度限制生效时整体收拢主题工作区，使页头、预览、参数及底栏保持对齐。底栏可用宽度低于 560 DIP 才换行，640 DIP 窗口保留单行操作以释放正文空间。

底栏固定“应用到设备”，保留“恢复默认”和“撤销”。无设备、副屏、暂停或熄屏时禁用应用并显示原因，编辑仍可预览。应用期间暂时禁用内容编辑，冻结本次内容与会话；发送后自动保存，保存失败提供仅本地重试。未取得设备呈现反馈时不宣称屏幕已显示。

切页保留内存编辑；撤销回到最近已应用内容。明确退出时有未应用更改则确认是否放弃，不提供另一套草稿保存流程。重连使用已确认的设备恢复配置。

## 5. 设置与诊断

### 5.1 设备设置

图像输出为主要分组。左侧屏幕方向示意配 0°／90°／180°／270° 单选项；右侧为帧率上限和 JPEG 画质，画质使用精确输入及滑块。方向图不再嵌套装饰容器，不重复解释字段含义。字段范围与默认值保持 0°、5fps、80，允许帧率 1～5、画质 70～85。已选择设备时页头显示当前设置归属的设备标识，不用状态徽章；无设备时由底栏说明不可用原因。

亮度是独立的紧凑横向分组，与图像输出间隔 32 DIP，不增加外层卡片：读回状态、0～100 滑块、精确输入和设置按钮。目标、已受理请求和实际读回不得混用；尚无读回时明确标注。保留“拖动即时生效”提示，拖动合并即时请求，数值输入需显式设置。该操作与图像输出的“应用设置”分开。

底栏为状态、恢复默认、撤销、应用设置；可用宽度低于 560 DIP 时换行。未连接时字段和设备动作禁用；当前参数从活动配置同步，不读取或保存设置草稿。恢复默认只改待应用字段。应用成功后自动保存恢复配置，失败保留编辑及错误；仅重试本地保存不重发设备操作。

### 5.2 应用设置

采用无边框设置行，按窗口与启动、设备模式、软件更新分组。组间留白 32 DIP，行间留白 20 DIP，以标签和控件的对齐建立对应关系，不逐行画分隔线。导航布局为两个文字单选按钮，关闭行为为下拉框，布尔设置为开关；自启注册结果单独显示。设备模式启用受限时显示连接要求，正常可编辑时不重复提示。默认值、验证和保存行为保持原规则。

内容宽度达到 820 DIP 时，窗口与启动位于左列，设备模式和软件更新位于右列；不足时按阅读顺序上下排列，组间仍保持 32 DIP。导航布局标签在两个选项上方，避免窄列内挤压控件。

导航选择立即预览，保存设置后持久化。底栏提供撤销更改和保存设置；重新读取仅在失败时出现，核实及取消按实际事务状态显示。撤销更改恢复已保存应用设置；切页保留未保存值。明确退出仍按保存／放弃／取消处理。

导航布局单选项获得键盘焦点时，四个方向键在顶部与侧边选项之间循环切换，同时移动焦点并立即预览；Tab／Shift+Tab 保持原有字段导航，不自动保存设置。

软件更新分组显示当前版本、自动检查设置与检查按钮；当前尚未接入更新服务，按钮禁用并说明原因，不显示“已是最新”。正式检查、下载、校验和安装流程按 PRD 与更新能力规格另行实施。

### 5.3 诊断

顶部三项摘要为传输状态、USB 已发送帧数、日志写入，以紧凑文本列展示，不使用大数字卡片。无设备时传输帧数显示“—”；设备呈现信息放在运行详情，不能把主机 USB 完成数改称实际 FPS。

运行详情折叠主机管线、设备反馈和日志存储明细。工具栏提供导出诊断及打开日志目录。下方为事件日志，表头与行使用相同列宽，适配覆盖式滚动条，显示时间、级别、阶段／事件、错误编号及当前条数。阶段与事件分行，警告和错误使用对应语义色及明确文字；空列表显示说明。最多 500 条，维持有限视口和容器虚拟化；高度不足时工作区可整体滚动。

## 6. 视觉设计令牌

数值为管理 UI 的 DIP，不是设备图像像素。下表是项目的语义令牌，颜色值是默认深色主题设计目标，并非 WPF UI 原生资源键。基础交互模板采用库资源，项目只覆盖必要的语义画刷、字体和间距；具体资源映射在 T-29 依据锁定版本验证。资源集中在 ResourceDictionary，页面不散落颜色和尺寸常量。

蓝色 #149CFF 统一用于主要操作、当前导航、主题模板选中边框、名称和勾选、导航布局选中边框、开启的开关、勾选的复选框及焦点；悬停／按下分别使用同一组状态色。WPF UI 的按钮、开关、复选框、下拉框焦点和选中标记、进度控件映射到项目语义色，不混用库默认强调色。普通图标、滑块和指标采用灰白。设备卡片选中用银白细边框，不将所有容器染色；次按钮用中性深灰。禁用提供原因；严重状态保留图形与文字。界面不使用大面积光晕、渐变玻璃或营销插画。

文字对背景对比度至少 4.5:1，必要边界与状态图形至少 3:1。高对比度开启时启用 WPF UI 的 HighContrast 主题，项目业务组件的语义画刷映射到 SystemColors 动态资源；固定深色与品牌色覆盖此时失效，使用系统背景、文字和选中颜色。自动化名称和文本状态始终保留。

App.xaml 依次合并 ThemesDictionary、ControlsDictionary、项目 ThemeOverrides；应用级主题适配器监听系统高对比度变化，开启时应用 HighContrast，退出时恢复 Dark。项目覆盖随主题切换同步更新，已打开的窗口、对话框和提示都必须响应。管理界面默认深色，不随系统普通浅色偏好改变。资源加载顺序与实际效果在 T-29 核验。[WPF UI 主题文档](https://wpfui.lepo.co/documentation/themes.html)

## 7. 尺寸、DPI 与布局规则

默认窗口参考 1180×820 DIP，兼容 1180×760 DIP；首次打开和恢复窗口位置时限制在当前显示器工作区内。不能用固定默认尺寸撑出屏幕。支持 640×400 DIP 的紧凑客户区；若系统可用工作区更小，窗口约束随之收缩并保留内容滚动。

| 客户区宽度 | 导航与内容 |
|---|---|
| ≥1000 DIP | 按偏好显示顶部或 184 DIP 侧边导航；主体按实际内容宽度采用双列，间隔 24～32 |
| 800～999 DIP | 保持所选布局；顶部放不下的入口收入更多菜单，主体优先单列 |
| <800 DIP | 两种布局统一使用折叠菜单，不改变已保存偏好；页头保留当前页中文名称和可命名的菜单按钮；展开后显示完整入口，选定即收起；主体单列，主动作仍可见 |

宽屏内容左右边距 32，紧凑窗口 16；表单标签在窄窗口移到字段上方。只在需要的主体区域滚动，避免多个嵌套 ScrollViewer。诊断表格保留独立有限高度以维持虚拟化。不要用 Viewbox 将整个窗口等比缩小，否则文字和交互目标都会变小。

设备预览按物理 W:H 适配容器，目标屏为 16:9。0／90／180／270°改变内容的逻辑布局，最终预览与设备帧仍对应同一物理 W×H；不通过拉伸填满空白。紧凑模式限制预览高度，不挤掉表单和操作区。

应用 manifest 声明 PerMonitorV2，布局使用 DIP 和矢量图标，关键边缘使用布局取整。验证 100%／125%／150%／200% 及不同 DPI 显示器之间移动；窗口 DPI 变化不改变设备帧像素尺寸。[Windows DPI 声明](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)

## 8. 交互、可访问性与提示

- 所有动作可用键盘完成；Tab 顺序与视觉顺序一致，Shift+Tab 可逆。Enter 触发焦点按钮，Esc 关闭当前对话框并归还焦点，不隐式撤销已发送的设备命令。
- 模式切换发出后不提供虚假的“取消切换”；可停止等待的操作也必须说明设备状态仍待确认。取消连接／恢复需要原生 I/O 收敛后才恢复可操作状态。
- 图标按钮有名称与 tooltip；选项有选中语义。状态变化适度通知读屏器，时钟和 1Hz 数值更新不持续打断朗读。
- 默认、悬停、按下、焦点、禁用、忙碌、校验失败和已选中均有完整样式。焦点框不被剪裁，状态不只靠颜色区分。
- 危险或有系统影响的操作才使用 ContentDialog 确认：首次离开副屏的窗口重排提示、退出切回副屏失败、放弃未保存应用设置、重启安装更新。普通保存与成功反馈使用页内状态及可收起的 Snackbar。
- 故障文案为“原因＋可执行动作＋错误编号”；操作失败提示持续可见。正常成功反馈可收起，但应用／保存状态仍可查询。
- 微交互仅用于悬停、按下和展开，约 100～160ms；不做循环装饰动画。遵循系统减少动画设置；等待只使用必要的进行中指示。

WPF UI 控件及主题化的 WPF RadioButton、ListBox、Slider、TextBox 均须验收键盘与自动化行为。重点检查 NavigationView 紧凑菜单、NumberBox 编辑与校验、ContentDialog 焦点约束和关闭后的焦点恢复；不能仅凭库支持主题就认定满足可访问性。自定义控件需补齐必要的 AutomationPeer 和 AutomationProperties，确保名称、角色、值与禁用状态可读。[WPF 自定义控件自动化](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/ui-automation-of-a-wpf-custom-control)

## 9. XAML 与 ViewModel 组织

```text
Desktop/
  MainWindow.xaml        FluentWindow、导航与唯一页面宿主
  Views/                 DevicesPage、ThemesPage、DeviceSettingsPage、ApplicationSettingsPage、DiagnosticsPage
  ViewModels/            对应页面状态、编辑内容、命令、校验
  Controls/              DeviceStatus、ThemeTemplatePreview、ColorPalette、InlineMessage；共享预览与设置行
  Resources/             SemanticResources、ThemeOverrides.Dark、ThemeOverrides.HighContrast
  Services/              导航、对话框、Snackbar、主题适配、文件选择、托盘、窗口行为
  App.cs                 依赖组合与生命周期接入
```

Shell 的顶部与侧边导航共用 NavigationView 导航服务及同一个内容宿主；切换布局只变更展示属性，保留五个页面实例。锁定版本不能直接提供顶部模板时，横排控件只转发原导航命令，不另建页面或会话。页面工厂和库导航服务由 Desktop 组合根配置，通过构造函数提供依赖；ViewModel 不读取全局容器。首版只有平级导航，不展示返回／前进按钮，缓存限定为五个已知页面，按锁定版本提供的机制限制或清理导航历史，避免反复切页持续增加内存。[WPF UI 导航文档](https://wpfui.lepo.co/documentation/navigation-view.html)

ViewModel 由组合根按窗口生命周期提供，编辑内容由窗口级 ViewModel 在内存中保留，设备会话由 ApplicationLifetime 持有。页面离开即解除快照订阅并停止该页预览通知，不能仅依赖缓存页面的 Unloaded 事件；重新进入读取最新快照并恢复编辑内容，不重复创建会话或提交命令。主窗口销毁时释放导航、主题监听与提示服务；隐藏到托盘时会话继续运行，UI 预览按架构暂停。

ObservableValidator 负责即时字段提示，Core 用例负责权威规则校验。异步命令返回 Task，错误由 UI 统一映射为页内反馈；ViewModel 不解析 USB 数据，不通过全局 Messenger 隐式控制设备。共享状态从不可变快照投影，视图双向绑定仅限编辑内容和请求输入。

颜色等需响应高对比度切换的资源使用 DynamicResource；不变的布局和模板可用 StaticResource。预览图不参加复杂布局动画。诊断列表同时限制数据条数并启用容器回收；UI 虚拟化不能代替数据上限。[WPF 控件性能](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)

DesktopThemeService 选择默认 Dark／系统 HighContrast，SemanticResources 提供语义键，ThemeOverrides.Dark 提供深色分层画刷。应用设置模型与存储持有 NavigationLayout，Shell 仅消费预览／已保存偏好；响应式布局为派生展示状态。以上为工程职责与目标文件组织，具体完成范围见 OpenSpec 任务和验证记录。

## 10. UI 验收矩阵

具体执行步骤在项目规范 TC-29～TC-33；下表为必须保留的可视证据。设计线框不能替代实现后的截图。

| 维度 | 最小覆盖 | 判定 |
|---|---|---|
| 有数据页面 | 首页活动主题、三个模板、两类设置、软件更新、诊断 | 中文、选中态、字段和动作位置正确，无占位样例冒充真实数据 |
| 生命周期 | 未连接、连接中、主题运行／暂停、熄屏、副屏、切换、恢复、故障 | 状态、预览来源和按钮一致，无虚假完成 |

| 导航与提示 | 顶部／侧边／紧凑导航、预览／撤销／保存／重启恢复、重复切页、打开／关闭确认、持续故障与短时成功提示 | 当前页与编辑内容稳定，历史有界，焦点正确返回，重要结果不随 Snackbar 消失 |

## 固件状态与关键流程画板

[设备状态与界面操作矩阵](contracts/ui-device-state-matrix.md) 定义现行 AD102 V2 下的全部门禁、默认值、恢复动作和需求追踪。页面、托盘与对话框共用该矩阵；它是本规范的组成部分。深色主题使用实色背景与面板。

SCREEN 下亮度、熄屏和唤醒禁用，保留原因说明；主题可编辑预览，应用按钮禁用并说明原因。Off 时禁止切模式；THEME 提供显式唤醒，SCREEN 不提供无协议支持的唤醒捷径。首次 SCREEN→THEME 显示 Windows 可能重排窗口的确认，可选择不再提示。模式 PID／HID 已确认与 Windows 桌面输出可用分开呈现。

画板 15～23 对应多设备选择、连接、SCREEN、Off、暂停、切换、未知、恢复和失败；24～25 对应托盘与退出；26～31 对应软件检查、发现版本、下载校验、安装确认、失败恢复和新版本确认；32 对应缺失与过期指标。首次切出确认及未应用内容退出确认按当前流程处理，05 自动检查默认开启。画板中的版本、数值与错误编号均为示例。

流程画板沿用 1180×820 画布、标题与状态卡、四阶段进度、常驻原因区及底部动作行。多设备选择使用单选列表，选择与连接分离；确认选择前主操作不可用。连接／切换／恢复使用不定进度，阶段由真实事件推进。未知结果的主操作为核实，恢复失败才按实际原因提供重新检测。取消等待后仍保持收敛门禁。托盘菜单使用原生命令项并同步禁用原因；退出对话框处理完未保存内容后再进入资源收敛，重试切换前先核实。

更新状态以独立状态模板呈现，不同时显示多个失败阶段的动作：检查失败→重新检查，下载或校验失败→重新下载，安装／启动失败→官方完整包和日志；更新源未配置时禁用检查并说明原因。下载未知总量及校验使用不定进度，只有真实字节数可计算百分比。待安装点击后弹 ContentDialog 确认，安全收敛期间禁止重复安装；新进程确认版本、配置和窗口／托盘初始化后才显示完成。

CPU、内存、PC 传感器和设备反馈分别标来源，缺失显示“不可用”；停更超过 3 秒保留最后值并标过期。固件温度／FPS 占位不能显示为真实零值；主机发送统计不能冒充设备实际 FPS。

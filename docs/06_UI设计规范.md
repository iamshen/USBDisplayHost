# USB Display 上位机｜UI 设计规范

版本：v0.5 WPF UI 展示层设计基线　日期：2026-10-07

## 1. 设计目标

采用 WPF/XAML＋WPF UI（lepoco/wpfui）的原生桌面工具，以设备状态、内容预览和当前动作形成清晰层级。界面采用浅色中性底、深色文字、蓝色主操作与适量留白。主窗口使用 FluentWindow＋TitleBar，保留最小化、最大化／还原、缩放、贴靠和系统菜单行为；这些行为须在目标 Windows build 上验收。

本规范是待实现的设计基线；下列线框、颜色和尺寸均为设计参数，不是运行截图或验收结果。产品行为以 [PRD](02_PRD.md) 为准，状态与线程规则以 [软件技术架构](03_软件技术架构.md) 为准。

首版交付浅色主题并适配系统高对比度。不新增应用深色模式设置；设备主题中的背景色不改变管理窗口样式。

WPF UI 提供通用窗口、导航、控件、主题、对话框和短时提示；项目组件负责设备状态、预览和持续错误。控件能力与 API 以锁定版本为准，依赖范围和版本管理见技术架构及项目规范。[WPF UI 官方仓库](https://github.com/lepoco/wpfui)

## 2. 信息架构与窗口骨架

固定五个一级入口：设备、主题、设备设置、应用设置、诊断。左侧导航顶部显示产品名，底部可显示应用版本；页头始终显示当前选定设备及连接状态。切页不建立或销毁设备会话，草稿不因切页丢失。

设备选择影响所有页面。切换选定设备先停止并释放旧会话，再打开新设备；已受理应用操作结束或取消收敛后才允许切换。草稿按设备键隔离；无设备草稿单独保存，选定设备后须显式应用，不能覆盖该设备的恢复配置。

| 区域 | 责任 | 展示规则 |
|---|---|---|
| 窗口标题栏 | 窗口名称、最小化、最大化、关闭 | FluentWindow＋TitleBar；保留 Windows 窗口操作；关闭默认进入托盘 |
| 左导航 | 页面定位 | NavigationView；图标＋中文名称；当前项同时有底色、指示条和选中语义 |
| 页头 | 标题、设备选择、连接状态 | 状态使用图形＋文字；操作号、PID 放诊断页 |
| 页面主体 | 预览、字段或诊断内容 | 一页一个主要任务；不堆叠无关指标卡片 |
| 页内反馈 | 本次操作结果、持续故障 | 位于相关内容附近；严重问题保留到解决或用户关闭 |
| 表单底部动作区 | 应用／保存草稿、恢复默认 | 在内容区占独立布局行，不覆盖滚动字段 |

### 2.1 控件映射

| 界面责任 | 控件／组件 | 使用约束 |
|---|---|---|
| 窗口与导航 | FluentWindow、TitleBar、NavigationView | 五个固定入口共用一个导航宿主；紧凑模式仍可读取中文页面名 |
| 设置字段 | WPF UI NumberBox 及主题化输入控件，配合 WPF Slider／RadioButton 等 | 常驻标签、单位与字段校验；数值范围来自 PRD，控件约束不能代替用例校验 |
| 主要／次要动作 | WPF UI Button | 每个操作区域突出一个主要动作；命令的忙碌与禁用状态来自 ViewModel |
| 需要决策的确认 | ContentDialog | 承载安装更新等现有确认流程；关闭后焦点回到触发位置，不增加普通保存确认 |
| 短时成功反馈 | Snackbar | 用于保存成功等可消失提示；结果仍在页面可查询，不承载唯一的错误或安装入口 |
| 持续状态与故障 | DeviceStatus、InlineMessage 业务组件 | 文字＋图形；设备反馈、软件更新状态与操作错误各自展示，不因 Snackbar 消失而丢失 |
| 图标与预览 | SymbolIcon／授权本地矢量资源、ContentPreview | 图标按钮有自动化名称；预览沿用独立内容管线，不渲染管理窗口控件 |

## 3. 设备首页

主题就绪时以真实物理比例的内容预览作为视觉中心，右侧显示当前模式、推流、电源、最近内容及简洁操作。PC CPU／内存和设备温度分组标注来源；高级吞吐统计在诊断页查看。

```text
┌ USB Display ────────────────────────────────────────────┐
│ 设备       │ 设备                 [当前设备 ▾]  主题就绪 │
│ 主题       │                                            │
│ 设备设置   │ ┌ 内容预览 ──────────┐  当前模式  主题模式   │
│ 应用设置   │ │                    │  推流      运行中     │
│ 诊断       │ │     物理屏幕比例   │  电源      已亮屏     │
│            │ │     的活动内容    │  当前主题  时钟       │
│            │ │                    │                      │
│            │ └────────────────────┘  [编辑主题]          │
│            │ 主机预览                [暂停] [熄屏]       │
│            │                         [切换到副屏模式]    │
│            │                                            │
│            │ PC 指标                    设备反馈         │
│            │ CPU 使用率／内存占用       温度／更新时间   │
└────────────┴────────────────────────────────────────────┘
```

线框中的状态仅示意布局；实现时全部来自实际快照。首页预览标“主机预览”，与主题页的“草稿预览”区分。预览不额外绘制一套时钟或仪表盘，直接呈现活动管线的最新结果。

| 首页状态 | 主体内容 | 主要动作 | 限制 |
|---|---|---|---|
| 未连接 | “未连接设备”；有历史内容时可显示并标“上次内容” | 重新检测 | 可进入主题编辑；历史预览不能带在线标记 |
| 首次连接且无活动内容 | 已识别的设备状态与中性预览占位 | 选择主题 | 不自动应用未确认的草稿 |
| 主题运行 | 活动内容预览、当前主题、推流与电源 | 编辑主题 | 暂停、熄屏和切副屏为次要操作 |
| 主题暂停 | 最后活动预览，标“已暂停” | 恢复主题 | 同会话恢复活动配置，不应用草稿 |
| 已熄屏 | 保留最后预览并标“已熄屏” | 唤醒 | 不把主机预览画黑当成真实设备反馈 |
| 副屏就绪 | “副屏模式”及真实连接信息 | 切换到主题模式 | 不展示伪造桌面镜像；可进入主题编辑 |
| 正在切换／恢复 | 目标状态、阶段文字及不定进度 | 查看诊断；恢复可停止 | 无百分比，无重复切换，不虚报回滚 |
| 故障／不兼容 | 原因、恢复动作和错误编号 | 重试／重新检测 | 根据错误提供一个最相关动作 |

模式操作使用“切换到主题模式／切换到副屏模式”按钮，当前模式用独立文本展示；不使用点击即选中的分段控件暗示切换已完成。模式与电源独立显示，连接中或结果未知时不能显示成功色。

## 4. 主题页

模板选择使用三个带名称与小预览的选项：图片、时钟、仪表盘。选中态具有边框、勾选和选择语义；不将整张不可聚焦的 Border 当按钮。主题参数在左，草稿预览在右。

```text
┌ 主题 ─────────────────────────────── [当前设备 ▾] ──────┐
│ [图片] [时钟 ✓] [仪表盘]                               │
│                                                        │
│ 内容与布局                    ┌ 草稿预览 ─────────────┐ │
│ 时间格式  [24 小时 ▾]          │                       │ │
│ 日期      [显示]              │    当前草稿的内容     │ │
│ 背景      [颜色]              │                       │ │
│ 文字      [颜色]              └───────────────────────┘ │
│                               未应用                   │
├────────────────────────────────────────────────────────┤
│ [恢复默认]                          [应用到设备]       │
└────────────────────────────────────────────────────────┘
```

模板字段保持首版最小集合：

| 模板 | 可编辑字段 | 校验与呈现 |
|---|---|---|
| 图片 | PNG/JPEG 文件、完整显示／填充裁剪、背景色 | 保持比例；透明部分合成背景；错误在文件字段下显示 |
| 时钟 | 12／24 小时、显示日期、背景色、文字色 | 时间来自本机；日期按本机区域格式；按 1Hz 刷新 |
| 仪表盘 | CPU 使用率／内存占用及可用温度项、背景色、文字色 | 明确 PC／设备来源和单位；缺失显示“不可用” |

采用固定模板布局，不加入拖拽排版、图层面板或通用主题编辑器。颜色选择使用少量可见色板与原生输入校验，所选颜色必须在草稿预览中即时反映。

应用之前不发送草稿。设备可接受主题时按钮为“应用到设备”；无设备、副屏态、暂停或熄屏时为“保存草稿”，仅保存本地编辑。切换进行中按钮禁用并显示原因，编辑内容继续保留。

点击应用后固定本次修订，按钮显示“正在应用”；再次编辑形成新草稿。结果分别展示“已发送”“已保存”和设备反馈。无呈现反馈时不显示“设备已显示”。保存失败使用“已发送，保存失败”和“重试保存”；重试不会重新发送主题或控制命令。失败不清空字段，不覆盖最近成功保存的恢复配置。

## 5. 设置与诊断

### 5.1 设备设置

分为“显示”“传输”“设备信息”三个纵向组。亮度使用 Slider＋NumberBox，并另列读回值；方向用四个带角度的选项，帧率与质量在“传输”组内使用 NumberBox。每个字段有常驻标签；单位紧邻数值，不依赖 placeholder。数值输入允许编辑中的临时文本，确认或失焦后仅提交通过校验的值；非法或越界输入不发送设备命令。

亮度属于即时控制：拖动时合并未发送的请求，释放后确保最终值提交；键盘方向键、Home／End 和数值输入同样可用。请求值与读回值不同则并列显示，不能把滑块目标值写成实际值。写入完成但无确认时显示“待确认”；确认成功后保存亮度意图，保存失败另示结果。

方向、帧率、画质属于待应用配置，通过本页“应用”生效；适用条件与主题应用一致。恢复默认只修改这些待应用字段，不即时改变亮度；亮度如需设为建议值，使用独立的“设为 80”动作。不支持的功能保留位置并注明原因；VNext 功能不显示入口。

### 5.2 应用设置

采用紧凑的“标题＋控件”设置行：关闭窗口行为、自启、启动自动切主题、退出策略、自动检查更新。默认值严格来自 PRD。设置项使用显式“保存”，切页保留未保存值；显式退出时对未保存设置提供保存／放弃／取消。系统关机不弹阻塞对话框。

软件更新放在本页独立分组，不增加一级导航。常驻显示当前版本和“检查更新”；有新版本时展示目标版本、下载大小和更新说明。更新动作立即执行，不依赖页面“保存”按钮；自动检查开关属于需保存的设置项。

| 更新状态 | 展示 | 可用动作 |
|---|---|---|
| 未检查／无更新 | 当前版本；最近成功检查时间或“尚未检查” | 检查更新 |
| 正在检查 | “正在检查更新”；不定进度 | 禁用重复检查，页面可切换 |
| 发现新版本 | 当前／目标版本、更新说明、下载大小 | 下载更新、稍后 |
| 正在下载 | 已下载／总字节、真实进度；总量未知时不定进度 | 取消下载；设备操作继续可用 |
| 正在校验 | “正在校验更新包” | 禁止安装，不伪造下载百分比 |
| 已下载 | “已下载，待安装”及固定目标版本 | 重启并安装、稍后 |
| 正在准备安装 | 保存内容、停止推流等当前阶段 | 禁止重复安装；不显示已更新 |
| 检查／下载／安装失败 | 具体阶段、恢复动作和错误编号 | 检查重试／重新下载／重试安装／获取完整安装包 |
| 新版本启动确认完成 | 当前版本、“已更新” | 检查更新 |

“稍后”保留现有工作，不设置隐式安装计划；再次启动仍须用户点击安装。后台发现新版本时只在应用设置导航旁给出非模态提示，不弹窗打断推流；后台检查失败不弹系统通知。安装确认文案为“安装更新将重启软件并短暂停止主题推流”，提供“重启并安装／取消”。

更新分组复用 WPF UI 的按钮、输入及进度样式，ContentDialog 承载安装确认，InlineMessage 保留检查／下载／安装失败。下载进度和更新结果由更新快照驱动；切页不重新检查或下载，取消或直接关闭确认框不安排安装。Snackbar 不作为更新状态的唯一载体。

设备切换或恢复进行中时，安装按钮禁用并在旁显示原因；检查和下载仍可进行。更新包已下载不改变首页的设备连接状态。当前为研发非安装版本时显示“当前版本不支持应用内更新”和正式下载入口，不把 SDK 的安装环境错误展示成“已是最新版本”。

### 5.3 诊断

顶部是版本、驱动、选定设备和最后错误摘要；下方是 PC 采样、主机传输和设备回传三组统计。设备解码／呈现无数据时显示“未提供”，不换用主机 USB 完成率填充。

最近事件列表最多保留 500 条摘要，启用 WPF 容器虚拟化；历史详情到日志文件查看。导出与打开日志目录为明确按钮，导出显示进行中与文件位置。列表不会每来一条数据就夺取焦点或强制滚到底部。

## 6. 视觉设计令牌

数值为管理 UI 的 DIP，不是设备图像像素。下表是项目的语义令牌，颜色值是浅色主题设计目标，并非 WPF UI 原生资源键。基础交互模板采用库资源，项目只覆盖必要的语义画刷、字体和间距；具体资源映射在 T-29 依据锁定版本验证。资源集中在 ResourceDictionary，页面不散落颜色和尺寸常量。

| 令牌 | 值 | 用途 |
|---|---|---|
| CanvasBrush | #F4F6F8 | 窗口内容背景 |
| SurfaceBrush | #FFFFFF | 表单与预览容器 |
| TextPrimaryBrush | #182230 | 标题、正文 |
| TextSecondaryBrush | #526071 | 次要内容、单位 |
| AccentBrush／OnAccentBrush | #245BDB／#FFFFFF | 当前页面的主要动作 |
| AccentHoverBrush／AccentPressedBrush | #1D4FC4／#1944A8 | 主按钮悬停／按下 |
| SelectionBrush | #EAF0FD | 选中导航和模板底色，文字用主色 |
| BorderBrush | #D4DAE3 | 容器分隔，不单独作为可操作边界 |
| ControlBorderBrush | #7A8798 | 输入框等控件边界 |
| SuccessBrush／WarningBrush／ErrorBrush | #176B45／#8A4B08／#B42318 | 与文本、图形共同表达状态 |
| FocusBrush | #245BDB | 2 DIP 焦点框；主色按钮外留白形成分隔 |
| Space | 4、8、12、16、24、32 | 图标、字段、分组、页面间距 |
| CornerRadius | 控件 6；容器 8 | 轻度圆角，不做大面积胶囊 |
| ControlHeight | 通常 36；工具按钮至少 32 | 高度为最小值，字体增大时可扩展 |
| IconSize | 导航 20；行内 16 | 优先 SymbolIcon，业务专用图标使用授权本地 Path／DrawingImage，统一轮廓风格 |

字体优先 Segoe UI，中文回退 Microsoft YaHei UI，使用系统已安装字体，不联网下载。字号：页标题 24、分组标题 16、正文 14、辅助信息 12；正文最小行高 20。长设备名允许换行或省略并提供可键盘访问的完整名称，错误说明换行展示。

文字对背景对比度至少 4.5:1，必要边界与状态图形至少 3:1。高对比度开启时启用 WPF UI 的 HighContrast 主题，项目业务组件的语义画刷映射到 SystemColors 动态资源；浅色覆盖此时失效，不能保留固定浅色底和品牌文字。自动化名称和文本状态始终保留。

App.xaml 依次合并 ThemesDictionary、ControlsDictionary、项目 ThemeOverrides；应用级主题适配器监听系统高对比度变化，开启时应用 HighContrast，退出时恢复 Light。项目覆盖随主题切换同步更新，已打开的窗口、对话框和提示都必须响应。首版不随系统深色偏好自动切成深色主题。资源加载顺序与实际效果在 T-29 核验。[WPF UI 主题文档](https://wpfui.lepo.co/documentation/themes.html)

## 7. 尺寸、DPI 与布局规则

默认窗口参考 1180×760 DIP；首次打开和恢复窗口位置时限制在当前显示器工作区内。不能用固定默认尺寸撑出屏幕。支持 640×400 DIP 的紧凑客户区；若系统可用工作区更小，窗口约束随之收缩并保留内容滚动。

| 客户区宽度 | 导航与内容 |
|---|---|
| ≥1000 DIP | NavigationView 左侧展开，宽 184；主体预览与控制双列，间隔 24 |
| 800～999 DIP | NavigationView 左侧展开，宽 152；主体优先保证字段宽度，不足时改纵向 |
| <800 DIP | NavigationView 使用 LeftMinimal 折叠菜单；页头保留当前页中文名称和可命名的菜单按钮；展开后显示完整入口，选定即收起；主体单列，主动作仍可见 |

页面边距常规 24，紧凑 16；表单标签在窄窗口移到字段上方。只在需要的主体区域滚动，避免多个嵌套 ScrollViewer。诊断表格保留独立有限高度以维持虚拟化。不要用 Viewbox 将整个窗口等比缩小，否则文字和交互目标都会变小。

设备预览按物理 W:H 适配容器，目标屏为 9:20。0／90／180／270°改变内容的逻辑布局，最终预览与设备帧仍对应同一物理 W×H；不通过拉伸填满空白。紧凑模式限制预览高度并提供展开查看，不挤掉表单和操作区。

应用 manifest 声明 PerMonitorV2，布局使用 DIP 和矢量图标，关键边缘使用布局取整。验证 100%／125%／150%／200% 及不同 DPI 显示器之间移动；窗口 DPI 变化不改变设备帧像素尺寸。[Windows DPI 声明](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)

## 8. 交互、可访问性与提示

- 所有动作可用键盘完成；Tab 顺序与视觉顺序一致，Shift+Tab 可逆。Enter 触发焦点按钮，Esc 关闭当前对话框并归还焦点，不隐式撤销已发送的设备命令。
- 模式切换发出后不提供虚假的“取消切换”；可停止等待的操作也必须说明设备状态仍待确认。取消连接／恢复需要原生 I/O 收敛后才恢复可操作状态。
- 图标按钮有名称与 tooltip；选项有选中语义。状态变化适度通知读屏器，时钟和 1Hz 数值更新不持续打断朗读。
- 默认、悬停、按下、焦点、禁用、忙碌、校验失败和已选中均有完整样式。焦点框不被剪裁，状态不只靠颜色区分。
- 危险或有系统影响的操作才使用 ContentDialog 确认：首次离开副屏的窗口重排提示、退出切回副屏失败、放弃未保存应用设置、重启安装更新。普通保存与成功反馈使用页内状态及可收起的 Snackbar。
- 故障文案为“原因＋可执行动作＋错误编号”；操作失败提示持续可见。正常成功反馈可收起，但应用／保存状态仍可查询。
- 微交互仅用于悬停、按下和展开，约 100～160ms；不做循环装饰动画。遵循系统减少动画设置；等待只使用必要的进行中指示。

WPF UI 控件及主题化的 WPF RadioButton、ListBox、Slider、TextBox 均须验收键盘与自动化行为。重点检查 NavigationView 紧凑菜单、NumberBox 编辑与校验、ContentDialog 焦点约束和关闭后的焦点恢复；不能仅凭库支持主题就认定满足可访问性。自定义控件需补齐必要的 AutomationPeer 和 AutomationProperties，确保名称、角色、值与禁用状态可读。[WPF 自定义控件自动化](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/ui-automation-of-a-wpf-custom-control)

## 9. XAML 与 ViewModel 组织

```text
Desktop/
  Views/                 Shell、Device、Theme、DeviceSettings、AppSettings、Diagnostics
  ViewModels/            对应页面状态、草稿、命令、校验
  Controls/              DeviceStatus、ContentPreview、InlineMessage 等重复组件
  Resources/             ThemeOverrides、Colors、Typography、Spacing、Icons
  Presentation/          预览解码、快照到 UI 的映射、Dispatcher 适配
  Services/              导航、对话框、Snackbar、主题适配、文件选择、托盘、窗口行为
  Composition/           依赖创建与 ApplicationLifetime
```

Shell 使用 NavigationView 及其内容宿主切换五个页面，所有页面共用这一导航入口。页面工厂和库导航服务由 Desktop 组合根配置，通过构造函数提供依赖；ViewModel 不读取全局容器。首版只有平级导航，不展示返回／前进按钮，缓存限定为五个已知页面，按锁定版本提供的机制限制或清理导航历史，避免反复切页持续增加内存。[WPF UI 导航文档](https://wpfui.lepo.co/documentation/navigation-view.html)

ViewModel 由组合根按窗口生命周期提供，草稿独立于页面缓存保存，设备会话由 ApplicationLifetime 持有。页面离开即解除快照订阅并停止该页预览通知，不能仅依赖缓存页面的 Unloaded 事件；重新进入读取最新快照并恢复草稿，不重复创建会话或提交命令。主窗口销毁时释放导航、主题监听与提示服务；隐藏到托盘时会话继续运行，UI 预览按架构暂停。

ObservableValidator 负责即时字段提示，Core 用例负责权威规则校验。异步命令返回 Task，错误由 UI 统一映射为页内反馈；ViewModel 不解析 USB 数据，不通过全局 Messenger 隐式控制设备。共享状态从不可变快照投影，视图双向绑定仅限草稿和请求输入。

颜色等需响应高对比度切换的资源使用 DynamicResource；不变的布局和模板可用 StaticResource。预览图不参加复杂布局动画。诊断列表同时限制数据条数并启用容器回收；UI 虚拟化不能代替数据上限。[WPF 控件性能](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)

## 10. UI 验收矩阵

具体执行步骤在项目规范 TC-29～TC-33；下表为必须保留的可视证据。设计线框不能替代实现后的截图。

| 维度 | 最小覆盖 | 判定 |
|---|---|---|
| 有数据页面 | 首页活动主题、三个模板、两类设置、软件更新、诊断 | 中文、选中态、字段和动作位置正确，无占位样例冒充真实数据 |
| 生命周期 | 未连接、连接中、主题运行／暂停、熄屏、副屏、切换、恢复、故障 | 状态、预览来源和按钮一致，无虚假完成 |
| 异常反馈 | 图片非法、字段越界、首帧失败、发送成功但保存失败 | 草稿保留、错误位置明确、恢复动作正确 |
| 窗口与字体 | 1180×760、800×600、640×400 DIP；系统文字放大；标题栏缩放／贴靠／系统菜单 | 无重叠和截断；主操作可达；长文案可阅读；窗口行为正常 |
| 导航与提示 | 展开／紧凑导航、重复切页、打开／关闭确认、持续故障与短时成功提示 | 当前页与草稿稳定，历史有界，焦点正确返回，重要结果不随 Snackbar 消失 |
| DPI | 100%、125%、150%、200%；混合 DPI 跨屏 | 界面清晰；弹窗可见；设备输出恒为物理尺寸 |
| 可访问性 | 全键盘、读屏器、高对比度、减少动画 | 名称与状态可读，焦点可见，无颜色或鼠标单一依赖 |
| 运行负载 | 5fps 活动主题＋连续编辑＋快速切页；窗口隐藏／恢复 | 操作受理≤200ms；不积压预览，不显示旧修订 |

V0 至少验收已实现主题范围的状态、布局、键盘与预览；V1 补齐双模、电源实机状态及软件更新全过程，更新功能另见 TC-34～TC-38。每组证据记录版本、窗口客户区尺寸、DPI、系统文字缩放、主题素材和设备状态来源。

# 上位机实现文档（USB Display 主题屏）

> 面向 **PC 端上位机软件**的工程落地文档：总架构、模块划分、双模切换逻辑、通信实现、验收清单。
> 协议细节（0xAF 帧格式、命令、rlx、EDID）见 `USB_副屏协议与局部刷新原理.md` Part B / 附录 C，
> 本文只在需要时引用，不重复定义。
>
> 适用：面板 VTDR6115 **1080×2400**（竖屏）/ AD100（Darwin RTOS）
> 最后更新：2026-10-05

**术语**

| 词 | 含义 |
|---|---|
| 副屏态 | 设备 PID = `0xAD11`，**Windows 显示驱动**接管，作为原生扩展显示器 |
| 主题态 | 设备 PID = `0xADA0`（自定义），**上位机**通过 WinUSB 独占端点推 0xAF |
| MI_00/01/02 | USB 接口号（display / vendor HID / touch HID） |
| 0xAF 通道 | Bulk OUT 数据面，只出不进 |
| 回传 | 设备 → 上位机，走 EP0 控制传输或 HID IN |

# 第一部分 总架构

## 1.1 系统总览

```
┌──────────────────────────── PC（Windows） ────────────────────────────┐
│                                                                        │
│  ┌── 应用层 ─────────────────────────────────────────────────────┐    │
│  │ 托盘UI │ 模式管理 │ 渲染引擎(主题/仪表盘) │ 硬件监控 │ 日志诊断 │    │
│  └───────────────┬───────────────────────────────────────────────┘    │
│                  │                                                     │
│  ┌── 传输层 ─────┴──────────────────────────────────────────────┐    │
│  │ libusb (Bulk OUT, MI_00)   │   hidapi (HID IN/OUT, MI_01/02)  │    │
│  └───────────────┬───────────────────────┬───────────────────────┘    │
│                  │                       │                            │
│  ┌── 驱动 ───────┴───────────────────────┴──────────────────────┐    │
│  │ 主题态: WinUSB(WCID)      │  副屏态: ingenic_display_driver   │    │
│  │ HID: 系统 hidusb.sys（两态都有，免驱，按接口类匹配）            │    │
│  └──────────────────────────┬────────────────────────────────────┘    │
└─────────────────────────────┼──────────────────────────────────────────┘
                              │ USB 2.0 High-Speed
┌─────────────────────────────┼─────────────── 设备（AD100） ────────────┐
│  ┌── USB Device ────────────┴───────────────────────────────────┐     │
│  │ MI_00 display (0xFF, Bulk OUT)  ← 0xAF 画面 + 命令            │     │
│  │ MI_01 HID vendor               → 状态/温度/ACK；← 控制命令    │     │
│  │ MI_02 HID touch (0x0D/0x04)    → 触摸坐标                     │     │
│  └──────┬───────────────────────────────────────────────────────┘     │
│  usb_display.c (收帧/拼帧/命令) → jpeg_display.c (jpegd 解码)          │
│                                        ↓                               │
│                              LCDC / DPU → 屏 (1080×2400)               │
│  触摸 IC (I2C: GT9xx/FT6236) → HID report                             │

```

## 1.2 分层与模块划分（PC 侧）

| 层 | 模块 | 职责 | 关键依赖 |
|---|---|---|---|
| UI | `TrayUI` | 托盘菜单、模式切换入口、设置面板、状态显示 | — |
| 控制 | `ModeManager` | **双模切换状态机**、PID 热插拔监听、超时/回滚 | libusb hotplug |
| 控制 | `DeviceSession` | 打开/关闭、端点发现、协商序列、SOFT_RESET | libusb |
| 数据面 | `FrameSender` | 0xAF 封包、分片、背压降帧、错误恢复 | libusb |
| 数据面 | `HidChannel` | HID IN 状态解析、HID OUT 命令、feature report | hidapi |
| 内容 | `RenderEngine` | 主题/仪表盘合成（Skia/Direct2D） | Skia |
| 内容 | `ScreenCapture` | 桌面镜像抓屏（可选） | DXGI |
| 内容 | `JpegEncoder` | JPEG 编码、质量/码率控制 | libjpeg-turbo |
| 内容 | `HwMonitor` | CPU/GPU/主板温度、风扇转速采集 | LibreHardwareMonitor(WMI) / NVML |
| 基础 | `Config` / `Logger` | 持久化、日志、诊断计数 | — |

## 1.3 通道矩阵

| 业务 | 通道 | 方向 | 可用性 |
|---|---|---|---|
| 画面（JPEG 帧） | **0xAF Bulk OUT (MI_00)** | PC → 设备 | **仅主题态**（副屏态被驱动占用） |
| 显示参数（亮度/分辨率/开关） | `0x20` 命令帧 | PC → 设备 | 仅主题态 |
| 自定义命令（待机/OTA/心跳） | `0x20` cmd `0x30+` | PC → 设备 | 仅主题态 |
| 设备状态（status/背光/EDID） | **EP0 控制传输** | 双向 | 仅主题态（需 claim） |
| 设备状态（温度/FPS/ACK/版本） | **HID IN (MI_01)** | 设备 → PC | **两态都有** |
| 控制命令（含**模式切换**） | **HID OUT (MI_01)** | PC → 设备 | **两态都有** ← 回程关键 |
| 触摸 | HID (MI_02 或 MI_01) | 设备 → PC | 两态都有 |
| 桌面画面 | Windows 显示驱动 | PC → 设备 | 仅副屏态 |

> **核心结论**：`MI_01` 的 HID 是唯一在两种状态下都存活的双向通道，
> **模式切换命令必须走 HID**（副屏态下 0xAF 端点被驱动独占，上位机根本发不了 0xAF）。

## 1.4 线程模型与数据流

```
HwMonitor线程(1Hz) ──► 温度快照 ──┐
                                  ├─► RenderEngine线程(fps) ──► 帧队列(depth=1~2)
ScreenCapture线程(可选) ──────────┘        │  (新帧覆盖旧帧, 丢弃积压)
                                           ▼
                                     JpegEncoder ──► FrameSender线程 ──► Bulk OUT
                                                            │
                                                       超时 → 降帧率
HidChannel线程(10~100ms) ◄── HID IN ── 状态/温度/触摸 ──► UI / ModeManager
libusb hotplug 回调 ──────► ModeManager（PID 变化 → 状态迁移）
```

**要点**

- **帧队列深度 1~2**：新帧覆盖旧帧，宁可丢中间帧也要保证"最新"，避免延迟累积
- 渲染与发送分离：编码耗时不阻塞 USB 写入
- HID 轮询独立：即使不推帧也能收状态/触摸
- 热插拔用 `libusb_hotplug_register_callback`（VID/PID 过滤），不要轮询枚举

## 1.5 背压与流量控制

设备端只有 4×256KB 预提交接收请求，**没有 IN 端点 → 没有端点级背压反馈**。

| 信号 | 判定 | 动作 |
|---|---|---|
| `libusb_bulk_transfer` 超时 | 连续 2 次 | fps 减半（最低 1fps） |
| 连续 32 帧成功 | — | fps 逐步恢复（×1.5 / 次，上限配置值） |
| 短写（transferred < len） | — | 视为失败，SOFT_RESET + 重发协商 |

**禁止无限重试** —— 会打满设备缓冲导致持续 `segbad`。


# 第二部分 设备形态与驱动绑定

## 2.1 两态定义

| | **副屏态** | **主题态** |
|---|---|---|
| PID | `0xAD11`（INF 列表内） | `0xADA0`（自定义，INF 列表外） |
| 接口 | MI_00 display + MI_01 HID (+MI_02 touch) | 同 |
| MI_00 归属 | Windows `ingenic_display_driver` | **WinUSB**（WCID 自动绑定） |
| MI_01 HID | 系统 `hidusb.sys`，**免驱** | 系统 `hidusb.sys`，**免驱**（按类匹配，与 PID 无关） |
| 谁推画面 | Windows 桌面扩展 | **上位机**（0xAF） |
| 上位机能做什么 | HID 查询 / 发切换命令 / 收触摸 | 全功能 |
| 用途 | 不用上位机时的原生副屏 | 主题、温度仪表盘、自定义内容 |

## 2.2 驱动绑定（主题态如何拿到 MI_00）

| 方案 | 机制 | 适用 |
|---|---|---|
| **A. WCID**（推荐，量产） | 设备端 EP0 响应 vendor 请求 `0xEE`（"MSFT100"）+ MS OS 扩展属性返回兼容 ID `WINUSB` | 免 INF、免签名 |
| B. Zadig（开发期） | 手动把 MI_00 绑到 WinUSB | 最快验证，不能量产 |
| C. 自写 INF | INF 匹配 `0xADA0` + 签名 | 有证书时 |

> 副屏态 MI_00 由官方驱动占用，上位机**无法** `claim_interface`。
> 这不是 bug，是 USB 端点独占 + Windows 驱动独占的必然结果 → **必须靠切换解决**。

# 第三部分 切换逻辑（核心）

## 3.1 为什么必须"切换"

1. **端点独占**：同一 Bulk OUT 端点同一时刻只能有一个主机端打开
2. **驱动独占**：副屏态下 Windows 显示驱动已绑定 MI_00，libusb 打不开
3. **驱动匹配靠 PID**：Windows 按 `VID&PID&MI_xx` 匹配 INF → 要让"谁接管 MI_00"改变，只能**换 PID + 重枚举**

→ 所以两态不能并存，只能**换 PID 重枚举**。好消息：**重枚举不黑屏**（LCDC 独立于 USB，保持最后一帧）。

## 3.2 状态机

```
                   ┌──────────── 切换失败/超时 ────────────┐
                   ▼                                       │
  [DISCONNECTED] ──枚举──► [SCREEN 副屏态]                │
                              │  │                        │
             用户切主题(HID)  │  │  用户切副屏(HID/0xAF)   │
                              ▼  ▼                        │
                    [SWITCHING 中间态] ───────────────────┘
                     · USB 断开重连
                     · LCDC 定格（不黑屏）
                     · 等待目标 PID 出现（超时 8s）
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
      [THEME 主题态]                   [SCREEN 副屏态]
      · claim MI_00                    · 释放 MI_00
      · 协商序列 → 亮屏                · Windows 驱动接管
      · 推帧循环                       · 仅 HID 监听
              │                               │
              └──────── 用户切副屏 ───────────┘
```

| 状态 | 进入条件 | 主要行为 | 退出条件 |
|---|---|---|---|
| `DISCONNECTED` | 无设备 | 监听 hotplug | 枚举到已知 PID |
| `SCREEN` | PID=`0xAD11` | 开 HID，监听状态/触摸，**不碰 MI_00** | 收到"切主题" |
| `SWITCHING` | 发出切换命令 | 等待目标 PID；倒计时 8s | 目标 PID 出现（成功）/ 超时（回滚） |
| `THEME` | PID=`0xADA0` + claim 成功 | 协商 → 推帧循环 | 收到"切副屏" / 退出 |

## 3.3 触发条件

| 事件 | 发起方 | 动作 | 备注 |
|---|---|---|---|
| 上位机启动，当前 `SCREEN` | 用户/自动 | 提示 → 切 `THEME` | 可配置"启动不切换" |
| 托盘 → 切到副屏 | 用户 | `THEME → SCREEN` | 上位机转入后台仅监听 |
| 托盘 → 切到主题 | 用户 | `SCREEN → THEME` | |
| 上位机退出 | 用户 | 可选：切回 `SCREEN` 或保持定格 | 默认保持定格（不黑屏） |
| USB 拔插 | 系统 | 重判状态 | 走到 `DISCONNECTED → 重枚举` |
| 切换超时 | 定时器 | 回滚原态 + 报错 | 见 3.7 |
| 设备无响应 | 诊断 | SOFT_RESET | EP0 `0xC1.03` |

## 3.4 副屏态 → 主题态（完整时序）

```
t0   当前 SCREEN：上位机只持有 HID
t1   通过 HID 发 CMD_SWITCH_MODE(val=0)        ← 只能走 HID！
       report: [2][0x31][0x00]...  (Output Report ID 2)
t2   设备端接收 → gadget_display_cleanup()
       → product_id = 0xADA0 → gadget_display_init() → USB 重枚举
       · LCDC 保持最后一帧（画面定格，不黑屏）
       · HID 接口短暂消失后重新出现
t3   Windows：display 设备消失 → 桌面重排（窗口被挪回主屏，固有代价）
t4   新设备枚举 PID=0xADA0：
       MI_00 → 无 INF 匹配 → 查 WCID → 装 WinUSB（首次 1~5s，之后 ~1s）
       MI_01 → HID，系统自动加载（与 PID 无关）
t5   上位机 hotplug 回调捕获 0xADA0
       → open → claim MI_00 → 端点发现
t6   EP0 读 specific descriptor 取分辨率 → GET_STATUS==0x18
t7   发协商序列（末尾 BLANK_MODE ON）→ 亮屏
t8   开始推帧循环
       可选：先推一张与旧画面接近的帧，或设备端做 alpha 淡化（需固件支持）
超时：t1 + 8s 未到达 t5 → 进入 3.7 回滚
```

```c
int switch_to_theme(mode_mgr_t *m)
{
    if (m->state != ST_SCREEN) return -1;

    /* 只能通过 HID —— 此时 MI_00 被 Windows 驱动占用 */
    if (hid_cmd_switch_mode(m->hid, MODE_THEME) != 0)
        return -1;

    m->state        = ST_SWITCHING;
    m->target       = ST_THEME;
    m->switch_deadline = now_ms() + 8000;

    /* hotplug 回调里等待 0xADA0 出现 → 完成 t5~t8 */
    return 0;
}
```

## 3.5 主题态 → 副屏态（完整时序）

```
t0   当前 THEME：上位机持有 MI_00 + HID
t1   优先通过 HID 发 CMD_SWITCH_MODE(val=1)
       （也可发 0xAF：AF 20 31 01，但 HID 更可靠，不受端点释放顺序影响）
t2   设备端 cleanup → product_id = 0xAD11 → init → 重枚举
t3   上位机 release_interface(MI_00)、停止推帧、关闭 libusb handle
t4   Windows：PID=0xAD11 → INF 匹配 MI_00 → 装/启用 display 驱动
       → 成为扩展显示器，Windows 自己开始推桌面
t5   上位机转入"仅监听"：保留 HID，继续收状态/触摸，随时可再切回
超时：t1 + 8s 未检测到 0xAD11 → 回滚（重发切主题命令）
```

> **退出上位机时不要发 `BLANK_MODE=0x02`(POWERDOWN)** —— 会触发设备复位
> （`usb_display.c:664-674`）。直接释放接口即可，画面定格。

## 3.6 切换期间的画面

| 阶段 | 画面 |
|---|---|
| 切换开始 | 保持最后一帧（LCDC 独立） |
| USB 断开重连（1~2s） | 仍保持最后一帧 |
| 新态就绪 | 新来源首帧直接替换 → **内容跳变** |

优化（可选，需固件支持）：设备端缓存最后一帧，与新来源首帧做 **alpha 淡化 200~300ms**，掩盖跳变。

## 3.7 异常与降级

| 故障 | 检测 | 处理 |
|---|---|---|
| 切换超时（8s） | 定时器 | 重发一次切换命令；再失败 → 提示用户 + 回到原态 |
| WinUSB 未绑定（主题态） | `claim_interface` 失败 / 设备管理器显示未知设备 | 提示用 Zadig 绑定 MI_00；或检查设备端 WCID |
| display 驱动未装（副屏态） | 设备管理器有未知设备 | 提示安装 `ingenic_display_driver` |
| 重枚举后无响应 | GET_STATUS != 0x18 | EP0 SOFT_RESET → 重发协商序列 |
| 切换后 HDI 丢失 | hid_open 失败 | 重新按 VID/PID 扫描 HID 接口 |
| 设备卡死 | 多次 SOFT_RESET 无效 | 提示用户重新拔插 USB |

**降级路径**：HID 不可用时（固件未实现），副屏态→主题态只能靠 **用户手动**（拔插 + 先不装 display 驱动），
或把默认 PID 设为 `0xADA0`（上电即主题态，副屏态变手动）。

## 3.8 切换相关命令定义

| 通道 | 命令 | 格式 | 说明 |
|---|---|---|---|
| **HID OUT (Report ID 2)** | `CMD_SWITCH_MODE` | `[2][0x31][val]` `val`: `0`=主题 `1`=副屏 | **推荐，两态都可用** |
| 0xAF | `AF 20 31 <val>` | 同上 | 仅主题态可用（此时端点已在上位机手里，其实没必要） |
| HID OUT | `CMD_SOFT_RESET` | `[2][0x30][0]` | 复位设备端 USB 队列 |
| HID IN (Report ID 1) | 状态位 bit3 `switching` | — | 设备端切换中置位，供上位机确认 |

> 设备端需实现：`0x31` 的 case（改 `product_id` + 重新 `usb_composite_probe`）。
> 未实现前，上位机应检测并隐藏"切换"入口（读固件 caps）。

# 第四部分 通信实现

## 4.1 会话状态机（主题态内）

```
[1] libusb_init → 枚举 0xADA0 → claim MI_00 → 找 Bulk OUT
[2] EP0 读 specific descriptor (0x81.06 wValue=0x1F00) 或 EDID → 取 w/h
      ⚠ 读到 1920x1080 说明设备端 EDID 未修，见 §6.6
[3] EP0 GET_STATUS (0xC1.01) == 0x18
[4] 发协商序列（末尾 BLANK_MODE ON）→ 亮屏
[5] 循环：渲染 → JPEG → 组帧 → bulk 写
[6] 退出：停推 → release_interface → close（不发 POWERDOWN）
```

### 端点发现（禁止硬编码）

```c
#define VID      0xa108
#define PID_THEME 0xada0     /* 主题态 */
#define PID_SCREEN 0xad11    /* 副屏态 */

typedef struct {
    libusb_device_handle *h;
    int iface, ep_out, w, hgt;
} disp_t;

static int find_display(disp_t *d, uint16_t pid)
{
    libusb_device **list;
    ssize_t n = libusb_get_device_list(NULL, &list);

    for (ssize_t i = 0; i < n; i++) {
        struct libusb_device_descriptor dd;
        libusb_get_device_descriptor(list[i], &dd);
        if (dd.idVendor != VID || dd.idProduct != pid) continue;

        struct libusb_config_descriptor *cfg;
        if (libusb_get_active_config_descriptor(list[i], &cfg) != 0) continue;

        for (int j = 0; j < cfg->bNumInterfaces; j++) {
            const struct libusb_interface_descriptor *id = &cfg->interface[j].altsetting[0];
            if (id->bInterfaceClass != 0xFF || id->bInterfaceSubClass != 0xFF) continue;

            for (int k = 0; k < id->bNumEndpoints; k++) {
                const struct libusb_endpoint_descriptor *ep = &id->endpoint[k];
                int bulk = (ep->bmAttributes & 0x03) == LIBUSB_TRANSFER_TYPE_BULK;
                int out  = (ep->bEndpointAddress & LIBUSB_ENDPOINT_DIR_MASK) == LIBUSB_ENDPOINT_OUT;
                if (!bulk || !out) continue;

                if (libusb_open(list[i], &d->h) != 0) break;
                d->iface  = id->bInterfaceNumber;
                d->ep_out = ep->bEndpointAddress;
                libusb_free_config_descriptor(cfg);
                libusb_free_device_list(list, 1);
                return libusb_claim_interface(d->h, d->iface);
            }
        }
        libusb_free_config_descriptor(cfg);
    }
    libusb_free_device_list(list, 1);
    return -1;
}
```

## 4.2 命令层

### 协商序列（必须按序，末尾 BLANK_MODE ON 才亮屏）

```c
static void send_cmd(disp_t *d, u8 cmd, u8 val)
{
    u8 f[4] = { 0xAF, 0x20, cmd, val };
    int t; libusb_bulk_transfer(d->h, d->ep_out, f, 4, &t, 1000);
}

static void disp_start(disp_t *d, int w, int h, int bl)
{
    send_cmd(d, 0x00, 0x01);              /* COLOR_FORMAT = RGB565 */
    send_cmd(d, 0x01, (w >> 8) & 0xFF);   /* WIDTH_HIGH  */
    send_cmd(d, 0x02, w & 0xFF);          /* WIDTH_LOW   */
    send_cmd(d, 0x03, (h >> 8) & 0xFF);   /* HEIGHT_HIGH */
    send_cmd(d, 0x04, h & 0xFF);          /* HEIGHT_LOW  */
    send_cmd(d, 0x05, bl);                /* BACKLIGHT 0-100 */
    send_cmd(d, 0x06, 0x00);              /* AUTORLX = 0（上位机恒关） */
    send_cmd(d, 0x11, 0x01);              /* MJPEG = 1 */
    send_cmd(d, 0x1F, 0x01);              /* BLANK_MODE = ON ← 亮屏 */
}
```

### 官方命令

| cmd | 名称 | val |
|---|---|---|
| `0x00` | COLOR_FORMAT | `0x01`=RGB565（建议）、`0x02`=XRGB888 |
| `0x01/0x02` | WIDTH_HIGH / LOW | 16 位拆分 |
| `0x03/0x04` | HEIGHT_HIGH / LOW | 16 位拆分 |
| `0x05` | BACKLIGHT | `0-100` |
| `0x06` | AUTORLX | `0` |
| `0x11` | MJPEG | `1` |
| `0x1F` | BLANK_MODE | `0x01`=ON；**`0x02`=POWERDOWN（会复位，禁用）** |

### 自定义命令 `0x30+`（需设备端加 case）

| cmd | 功能 | val |
|---|---|---|
| `0x30` | 软复位/重连 | — |
| `0x31` | **模式切换**（切 PID 重枚举） | `0`=主题 `1`=副屏 |
| `0x32` | OTA 裸流 | — |
| `0x33` | 开机动画下载 | — |
| `0x34` | 旋转 | `0/1/2/3` |
| `0x35` | 待机息屏定时 | 秒 |

| `0x37` | 画质/帧率档位 | 档位 |

> 上位机应先查固件能力，不支持则隐藏相关入口。

## 4.3 推帧管线

### 封包规则

- 片头：`AF <type> <src_offset:3B BE> <size:3B BE> [pixel_offset:3B BE] <data>`
- `0x69` = 帧尾（带 `pixel_offset`），`0x68` = 中间片
- **小帧推荐只用一片 `0x69`**
- `src_offset` 必须严格连续，否则 `segbad++` 整帧作废
- 每片必须**完整落在同一次 bulk 传输内**
- 单帧 ≤ **1MB**，必须以 `FF D8` 开头
- 全帧 MJPEG 时 `pixel_offset` 恒为 0

### 实现

```c
#define CHUNK_MAX (240 * 1024)

static int send_jpeg(disp_t *d, const u8 *jpg, size_t len)
{
    if (len > (1u << 20)) return -1;          /* 单帧上限 1MB */
    size_t off = 0;

    while (off < len) {
        size_t remain = len - off;
        int    last   = (remain <= CHUNK_MAX);
        size_t hdr    = 1 + 1 + 3 + 3 + (last ? 3 : 0);
        size_t payload = (remain <= CHUNK_MAX - hdr) ? remain : (CHUNK_MAX - hdr);

        u8 *buf = malloc(hdr + payload), *p = buf;
        *p++ = 0xAF;
        *p++ = (off + payload >= len) ? 0x69 : 0x68;
        *p++ = (off >> 16) & 0xFF;  *p++ = (off >> 8) & 0xFF;  *p++ = off & 0xFF;
        *p++ = (payload >> 16) & 0xFF; *p++ = (payload >> 8) & 0xFF; *p++ = payload & 0xFF;
        if (last) { *p++ = 0; *p++ = 0; *p++ = 0; }   /* pixel_offset = 0 */
        memcpy(p, jpg + off, payload);

        int t = 0, r = libusb_bulk_transfer(d->h, d->ep_out, buf, hdr + payload, &t, 2000);
        free(buf);
        if (r != 0 || (size_t)t != hdr + payload) return -2;
        off += payload;
    }
    return 0;
}
```

### 帧率与带宽（1080×2400）

| 场景 | JPEG q80 单帧 | 建议 fps | 码率 |
|---|---|---|---|
| 静态主题（时钟/壁纸） | 80–150 KB | 1 / 按需 | ~0.1 MB/s |
| 温度仪表盘 | 150–250 KB | 2–5 | 0.3–1.2 MB/s |
| 动态主题/动画 | 250–400 KB | 10–15 | 2.5–6 MB/s |
| 桌面镜像 | 300–600 KB | 15–30 | 5–18 MB/s（需实测解码） |

USB HS bulk 理论 ~40 MB/s，**瓶颈在设备端 jpegd 解码 1080×2400** → 从 5fps 起步实测。
静态内容不推帧（画面定格即可）。

## 4.5 HID 报告格式（需设备端实现）

**Input Report ID 1（64B，设备 → PC）**

| 偏移 | 字段 |
|---|---|
| 0 | Report ID = 1 |
| 1 | 状态位：bit0 display_enable / bit1 autorlx / bit2 拼帧异常 / **bit3 switching** |

# 第六部分 工程化

## 6.1 错误处理

| 现象 | 排查 | 处理 |
|---|---|---|
| `claim_interface` 失败 | 驱动占 MI_00 | 切主题态 PID / Zadig |
| 画面不出 | 未收到 BLANK_MODE ON | 重发完整协商序列 |
| 花屏/错位 | 分片跨传输 / `src_offset` 不连续 | 每片独立一次 bulk |
| 帧被丢弃 | >1MB 或缺少 `FF D8` | 降 quality |
| `segbad` 飙升 | 拼帧错乱 | EP0 SOFT_RESET + 重发协商 |
| bulk 写超时 | 设备接收请求打满 | **降帧率，不重试** |
| 连不上 | 设备在 CDC 模式 | 改固件默认 Display，或先 CDC 发 `0x16 [1]` |

```c
int main(void)
{
    disp_t d = {0};
    if (disp_open(&d) != 0) { printf("device not found\n"); return 1; }
    disp_start(&d, d.w, d.hgt, 100);

    int fps = 5;
    while (!quit) {
        u8 *jpg; size_t len;
        render_theme(&jpg, &len, d.w, d.hgt);
        if (send_jpeg(&d, jpg, len) != 0) {
            libusb_control_transfer(d.h, 0xC1, 0x03, 0, d.iface, NULL, 0, 500);
            disp_start(&d, d.w, d.hgt, 100);
        }
        free(jpg);
        sleep_ms(1000 / fps);
    }
    disp_close(&d);      /* 不发 POWERDOWN */
    return 0;
}
```

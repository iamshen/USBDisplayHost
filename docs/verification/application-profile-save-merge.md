# 应用恢复配置存储门内合并代码基线

关联 REQ-06／REQ-08、FR-06／FR-08、D3、T-16／T-30，任务 7.4／7.5。仅有代码与目标 Release 编译证据。

IProfileStore.SaveApplicationAsync 已提供主题／设置应用的独立保存职责，返回 ProfileApplicationSaveAttempt，包含实际合并候选及独立文件写入结果。ThemeApplicationService 的首次发送后保存与仅本地重试均使用该入口，不再整份调用 SaveAsync 写回发送前读取的旧控制字段。

FileProfileStore 在现有共同 StorageBoundary 内重新读取该设备主恢复配置，核对永久键和最新主题／设置是否仍为原恢复基线或本次候选，再合并并写入；读取、素材预检／持有及 AtomicJsonStorage 写入全过程不离开同一门。主题／设置改变为另一配置时不写，主文件未确认、只剩备份／默认／未来版本或原存在配置现在缺失时不推断控制字段，也不覆盖。保留已有恢复资料，由用户核实后处理待保存候选。

亮度或电源字段相对原恢复基线已改变时保留当前主文件值，否则沿用本次已确认应用基线值。主题候选保留本次冻结设置，设置候选保留本次冻结主题；门内合并不重发画面、不发送亮度／电源命令，不修改活动提交或后续草稿。原整体 SaveAsync 尚保留接口，但当前主题应用路径已不使用；实际控制保存适配器尚未实现，不能由此声称完整控制写入共同责任已交付。

实际写入开始前冻结 merged 候选。写入返回结果与候选一起交给 Core；写入后的存储边界取消／普通异常也转为包含实际候选的 Unknown 写入结果，不丢失合并过的亮度／电源值。Core PendingThemeSave 保留这份候选，原 Unknown 重试继续只读核实 Primary 与完整 DeviceProfile 相等，不能用旧候选、主题字段匹配或备份代替完整保存确认。写入前失败保持明确 Failure，不把保存失败变成发送失败。

Core 在接收合并收据时再次核对候选存在、同设备键／冻结主题／设置、有效亮度与电源枚举及独立写入结果存在；仅允许控制字段合并，不允许存储结果改换已经发送的内容。收据不完整或不匹配时保留原待保存候选／RetryId／素材，并标 Unknown 和 CanVerifyProfile=false，不接受碰巧匹配原文件的读回作为异常写入确认，不读取或重写文件。主题与设备设置页禁用该记录的重试，已有显式退出按 RetryId 处理本地记录的路径继续适用；不能由放弃确认推断文件回滚。普通文件写入 Unknown 若收据有效，仍保留实际合并候选并允许原主文件精确核实。收据异常路径未运行验证。

该门只串行本进程同一存储协调器的调用，不证明外部进程或文件系统替换隔离。备份／损坏恢复后的明确重新保存策略和实际控制写入仍需完成，磁盘故障／并发写入／未知结果行为尚未运行观察。

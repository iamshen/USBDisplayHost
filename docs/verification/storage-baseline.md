# 本地配置与素材实施状态

日期：2026-10-08。关联 T-18，OpenSpec 7.1、7.2。

## 配置文件

当前用户目录为 `%LocalAppData%/UsbDisplayHost.Data`，与安装和更新缓存分开。`application-settings.json` 保存应用设置，`profiles/` 保存各设备恢复配置，`drafts/` 保存各设备草稿及独立的 `offline.json`。

设备文件名使用稳定设备键的 SHA-256，不把序列号、PID 或外部路径当作文件名；文件内仍核对所属设备键。恢复配置不等同设备实际反馈，也不会从草稿自动生成。当前会话 ActiveProfile 由 Core 用例持有，其生命周期和应用事务尚未接入。

JSON 新写 schemaVersion=2 和类型化 data，可读取版本 1／2；应用设置新增可选 CloseToTray，旧格式缺失时默认收至托盘。读取不自动改文件，显式保存才提交新版本，旧版本程序可通过高版本识别保护文件。使用严格构造参数、深度限制及 256KiB 配置读取／写入上限。缺失、主文件、备份恢复、默认降级、未知高版本均有独立结果；草稿的恢复状态、可用值和错误一起返回，损坏不被伪装成没有编辑。

保存先序列化和验证，再写同目录临时文件、刷新、提交；已有有效主文件以 File.Replace 更新并备份。损坏主文件不覆盖最近可用备份，而是保留按内容哈希命名的 `.corrupt-*` 副本后替换主文件。同一损坏内容不重复积累副本。任何未知高版本主文件或备份都阻止写入；过大文件保留原件且拒绝覆盖，不复制巨型输入。

取消在提交前检查；File.Replace／File.Move 前标记提交边界，普通异常分为准备阶段 Failure 和提交阶段 Unknown，替换异常不会再被外层存储边界当作确定未保存。提交后重新打开主文件只读句柄，在 256KiB 上限内核对实际长度和完整字节，并等待句柄关闭后才返回 Success；不使用用户取消令牌提前退出提交后核实。不匹配、读取或关闭异常保留错误编号并返回 Unknown，由现有草稿／应用设置／恢复候选核实入口处理，不直接重写。后续临时文件清理失败单独记录，不改写已确认结果。界面不显示内部路径或堆栈。上述是代码与编译证据，实际权限、占用、磁盘、取消或提交故障尚未运行验收，已接入结构化日志，运行与故障验收仍属 8.3。

## 素材

PNG/JPEG 导入先检查大小和头部尺寸，复制到 assets 目录的临时文件，经注入的 STA 完整解码验证后提交。正式文件使用随机 32 位十六进制标识，不依赖原文件，读取只接受该标识；源路径不是恢复配置的一部分。失败／取消不提交正式素材，临时文件清理失败可记录。

素材引用索引、活动／在途租约及无引用清理尚未实现；当前不删除已导入素材。7.2 保持未完成，后续必须同时覆盖草稿、活动、恢复配置和在途应用引用，不能用仅扫描恢复配置的清理替代完整要求。

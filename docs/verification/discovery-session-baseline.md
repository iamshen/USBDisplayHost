# 设备发现生命周期代码基线

关联 REQ-01／FR-01、D2／D3、T-09，任务 4.2。

`WindowsDeviceDiscoverySession` 成功创建后拥有 WindowsDeviceDiscovery，最多八个强引用所有者，同一发现服务不能重复接管。调用方只消费一个最新快照通道，不直接再消费发现流、枚举或关闭底层服务。创建不创建原生监视器，但会启动已创建发现服务的订阅与枚举循环；App 尚未调用此入口。

监视器注册后已经提供初始重扫通知。生命周期收到实际 WatchAsync 通知后才允许初次枚举；订阅提前结束或异常阻止枚举并发布带错误编号的失败快照。通知和手动重扫合并到一个待处理槽，单枚举循环保证串行，完成同一请求后不重复消费其残留信号。快照同样只有一个最新槽，生产者不等待 UI。

重扫立即清空可选择列表；请求版本变化时旧枚举结果不发布。仅完整成功结果重新开放选择，失败／取消／未知结果不把旧列表当成当前事实。未知结果停止后续枚举；快照版本耗尽停止选择，不回绕。选择要求精确当前快照版本，使用 Core DeviceSelectionResolver 再次核对永久键、容器关联与重复身份歧义，不自动选择或连接。选择是当次列表核验结果，后续连接仍须重新核对当前通知代次与实际设备，不能将选择成功当作设备 Ready。

关闭先停止请求并撤销选择资格，取消且等待通知／枚举循环，再确认发现服务有序关闭。关闭任务只执行一次，原生关闭未知时强引用保留生命周期和底层所有者，发布错误但不释放预约。同步驱动调用有界退出未证明，未丢弃在执行任务或声称取消已完成原生释放。

仅运行目标 Release 构建，四个生产工程 0 警告、0 错误。未创建或执行测试，未运行循环、调用原生接口、打开设备或启动窗口。页面发现列表／选择展示、App 组合、断开对活动会话的通知、实际兼容记录和热拔插／多设备验收仍未完成；4.2 父项保持未完成。

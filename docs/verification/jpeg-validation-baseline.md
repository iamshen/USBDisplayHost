# 设备帧 JPEG 校验实施记录

关联：REQ-03／FR-03、T-10、任务 4.5、jpeg-frame-transport。日期：2026-10-08。

## 生产模块

Core 的 `JpegStructureInspector` 在最多 1MiB 输入内检查 SOI、完整分段、唯一 SOF、SOS、扫描字节及最终 EOI；拒绝截断、尾随字节、拼接图、独立重启标记、未支持的编码和未知标记。核对量化／Huffman 表长度及定义、扫描分量与表引用、重启启用状态和顺序。长度计算均在切片前核验，结构失败返回错误编号，不抛出预期的输入错误。

当前主机实现范围为 8 位 SOF0／SOF1／SOF2、1 或 3 分量、8 位量化表；检查分量顺序／标识与水平垂直采样因子，拒绝重复标识、零尺寸及超过 2000 万像素的结构。标记和字段依据 [ITU-T T.81 JPEG 标准](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)。这份实现范围不是固件支持声明；算术、无损、层次编码、DNL 和 16 位量化表均不放行。

`FirmwareJpegProfile` 必须显式提供固件版本、兼容证据引用及不超过 16 种精确格式；没有默认兼容清单。仅建立该对象不能证明证据有效，后续组合入口仍须从已冻结兼容记录提供它。

Rendering 的 `WpfJpegFrameValidator` 要求已验证设备能力、同版本固件清单、活动帧上下文、1920×1080 尺寸和双方帧长上限；结构中的尺寸／格式必须匹配。之后使用 JPEG 专用 WPF 解码器并读取全部物理像素，每次最多 32 行 BGRA 缓冲，不应用素材 EXIF 旋转或 DPI 缩放。结构检查不能代替解码，WPF 解码也不能代替固件兼容性。解码器自身的容错行为及扫描语义仍须用真实样本核验，没有声称逐位验证了全部压缩熵语法。

一次只执行一个解码，持有最多 1MiB 自有 JPEG 副本。取消等待工作槽可直接返回；开始 STA 解码后等待实际结束再释放工作槽。普通线程启动／解码异常返回失败并记录错误编号，不自动重试。此模块不调用 USB、不修改活动配置；未来发送入口还须重新核对设备键／代次／修订及协调器当前操作，校验成功不代表仍可发送。

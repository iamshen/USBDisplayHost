# 活动主机预览代码基线

关联 REQ-04／FR-04、D3、T-29／T-30，任务 3.3。仅有代码与目标 Release 编译证据。

FrameBoundaryScheduler 在帧写入成功且原 I/O drain 已确认后，核对原帧上下文、编号、JPEG 长度和完整包收据，再将实际 EncodedFrame 与收据保留在一个 CompletedHostFrame 最新槽，不复制 JPEG，不创建预览渲染循环。首帧收据本身不等于活动提交：ThemeSessionPipeline.CaptureActiveHostFrame 同时要求当前 ActiveProfile 的设备键／代次／操作／管线修订匹配，并在取值后再次核对活动配置未变化；未提交首帧、旧配置或旧会话不返回当前活动画面。

DeviceSessionLifetime 只从当前 owner 读取该槽。设备页可见时原页面 DispatcherTimer 每秒取一次最新画面，最多一个解码任务在途；BitmapImage 在后台以最多 576 像素宽、OnLoad 解码并 Freeze，回到页面线程后再次核对可见修订和最新同一 CompletedHostFrame 才更新。只有一个 UI 图片槽，不保存图片列表或排队 Dispatcher 通知，不等待 UI 才完成 USB 发送；实际分配／时延未测量。

同一上下文／帧编号已显示时不再解码。解码失败保留错误编号和失败编号，同一失败帧不由定时器自动重试；提供“重试预览”。隐藏页面／窗口不开始新解码，隐藏后到达的结果不呈现；显示后取当前最新槽，不积压帧。发现关闭先停止设备页选择／预览并等待在途解码，后续才释放发现、协调器及共享工作区。

当前活动画面未提供时保留至多一个旧 Bitmap 并标“上次主机画面”，同时标其原设备；选定另一设备键时清除旧图片，避免混用。标签明确主机预览和呈现反馈未提供，不显示副屏桌面镜像、不将 Off 预览画黑、也不把草稿 JPEG 当作活动内容。已有独立 DeviceStatus 继续提供模式／电源／推流状态。当前 App 没有实际设备管线，预览保持尚无已提交画面。

目标 Release 构建四生产工程 0 警告、0 错误，`git diff --check` 通过。未创建或运行测试、WPF 窗口、预览／解码循环或设备请求，无截图。真实运行的候选提交、换设备／隐藏竞态、长期内存、紧凑布局及视觉／辅助技术尚未验收；3.3 父项保持未完成。

# 磁盘素材引用扫描实施记录

关联：REQ-04／FR-04、REQ-08／FR-08、T-18、任务 7.2、TC-14／TC-26。日期：2026-10-08。

Core IAssetReferenceInventoryStore 返回只读素材标识集合及配置文件数量。Windows FileProfileStore 在与自身全部读写相同的 StorageBoundary 中执行扫描，因此该实例的配置写入不会插入扫描过程；没有暴露原生句柄或磁盘路径到 Core 结果。

扫描范围为 profiles、drafts、device-settings-drafts 的全部顶层条目，主 JSON 和各自 .bak 分别验证，不以恢复选择的优先级忽略备份引用。接受既有 schemaVersion 1／2，复用严格字段解码、主题／设备设置校验及设备键规则。文件名须匹配设备键 SHA256 归属路径，无设备草稿只能匹配 offline.json；图片标识统一小写去重。

先核实数据目录顶层：只接受五个已定义目录（profiles、drafts、device-settings-drafts、assets、diagnostics）及 application-settings.json／.bak，最多七个条目；未知目录、文件、临时或损坏副本、重解析项阻止完整扫描。应用设置主文件／备份逐个检查大小、schemaVersion 1／2 及现有严格字段解码，并计入配置文件数量；已知设置没有素材字段，但未知版本不能据此推断无引用。该步骤不递归扫描日志或把用户未知文件自动归为可忽略项。

最多核实 4096 个文件，每个文件限 256KiB、JSON 深度 16。空文件、过大文件、未知版本／字段、无法解析的身份、归属错误、读取故障、未知条目、临时文件、损坏副本、子目录及重解析项阻止完整扫描，返回带编号的失败；不返回一个“已完整核实”的部分集合。仅实际文件／目录缺失视为无该引用来源，其他访问异常交由存储边界反馈。损坏副本可能仍包含无法恢复的素材引用，不能直接忽略后清理。

扫描直接只读打开并解码文件，不使用 AtomicJsonStorage.ReadAsync 的恢复／损坏副本生成路径，不修改配置、创建损坏副本、保存备份或删除素材。仅核实已定义配置来源与顶层目录形态，不解析用户导出文件内容或未知未来配置；遇到顶层未知来源时明确阻止完整扫描。

结果是当次快照，不是删除授权；文件读取结束后不持有跨操作磁盘锁，不能阻止其他存储实例、外部程序或稍后写入修改引用。清理仍须把扫描、素材租约与配置／素材写入纳入同一所有者和同一清理事务，并核实数据目录中的未知格式。尚未接入实际清理入口，不按零进程内租约或旧扫描结果直接删除。

# WinUSB 打开发现凭据代码基线

关联 REQ-01／FR-01、D2／D3、T-09，任务 4.2／4.3。

WinUsbDisplayTransport 构造需要 DeviceSelectionAdmission，Core IDisplayTransport 接口继续只接收设备身份，不向 ViewModel 暴露原生句柄。正式工厂也要求同一凭据，身份必须完整属于冻结的选定接口集合，不能拿另一身份搭配相同永久键打开。

后台打开在路径预约前、预约后／CreateFile 前、文件打开后／WinUsb_Initialize 前、端点核验后／策略设置前以及完成 PnP 核验后的交付前核对凭据。发布可复用活动身份后再核对一次；变化则撤回身份，拒绝交付并走既有 associated／primary／file 的确认释放顺序。期间取消不丢弃打开任务。凭据核验普通异常沿用带错误编号的打开失败结果，清理未确认覆盖为 Unknown，不能以失败或取消声称句柄已释放。

共用路径预约在任何正式原生打开前强引用 WinUsbSessionFactory。工厂持有成功会话或未知清理所有者，使其跟随路径占用保持可达；路径只能在文件和 USB 释放确认后清除该资源引用。此所有权只覆盖本进程，不能代替外部进程互斥。探测器继续使用其既有强引用所有权。

没有引入默认接口、固件、控制报告或模拟成功观察。核验是各受理／交付点的内存观察，之后到达的移除仍由通知／协调器代次失效链处理；实际连接用例还需核对操作上下文、设备模式、电源及能力，成功打开不是 Ready。

仅运行目标 Release 构建，四个生产工程 0 警告、0 错误。未创建或执行测试，未打开接口、调用原生 API、设置策略或启动窗口。App 正式连接、控制契约、实际快速重插／释放及多设备验收仍未完成；4.2／4.3 父项保持未完成。

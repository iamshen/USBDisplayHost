# 休眠／唤醒会话失效代码基线

关联：REQ-09／FR-09、T-13、任务 5.5、9.4。

App 为实际主窗口附加一个 WindowPowerLifetime。窗口源建立后订阅 HwndSource；处理 WM_POWERBROADCAST 的休眠与自动唤醒通知。通知定义依据 [WM_POWERBROADCAST](https://learn.microsoft.com/en-us/windows/win32/power/wm-powerbroadcast) 和 [PBT_APMRESUMEAUTOMATIC](https://learn.microsoft.com/en-us/windows/win32/power/pbt-apmresumeautomatic)。自动唤醒与随后用户活动不是两个恢复周期，后者不重复处理。应用不解析原生数据指针、不阻止系统休眠，不判断具体低功耗状态。

通知回调只读取协调器和生命周期的不可变已发布快照，冻结当时的选择设备／代次及管线所有者／代次，保留各一个休眠／唤醒待处理记录和容量一信号。不执行设备关闭、发现、文件写入或等待 UI。生命周期快照通过 Volatile 发布与读取，不在回调等待会话接管锁。休眠记录与唤醒记录分开，快速唤醒不会覆盖唯一待处理休眠动作。

一个后台消费者使记录内的原选择失效，并按记录内原管线身份请求现有缓存关闭链。迟到事件不读取新选择来决定关闭目标；不同设备或新代次不被旧事件失效。自动唤醒也执行原会话失效，不以曾收到休眠通知为前提。未知关闭和待保存本地结果由原 DeviceSessionLifetime 保留，不重放 Native 关闭，不丢弃配置或改动草稿。

唤醒后只有实际管线不再保留且没有会话操作在途，才请求已经附加的发现生命周期重扫；没有附加时不创建监视器或虚报发现已运行。重新连接仍须明确选择与实际发现凭据，不能自动切主题、点亮设备、读取草稿发送或复用旧句柄。失败时原常驻会话错误／生命周期结果可见，实际操作异常记录诊断。

工作区停止先在窗口线程解除电源订阅，再等待消费者结束，随后进入原会话／发现／页面／渲染等关闭链。订阅停止未知时保留后续资源；关机仍受已有结果观察预算及操作系统期限限制。不将订阅解除解释为原生设备资源全部释放。

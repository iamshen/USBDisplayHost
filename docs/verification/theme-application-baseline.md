# 主题应用事务实施记录

关联：REQ-04／FR-04、REQ-06／FR-06、REQ-08／FR-08、T-30、任务 7.3／7.4／7.5、TC-31／TC-32。日期：2026-10-08。

## 候选与活动提交

Core `ThemeApplicationService` 接受冻结的主题或设备设置草稿和受理操作上下文，不修改草稿、不清除后续编辑。要求设备键与草稿修订匹配操作；校验内容，读取恢复配置，拒绝未知高版本。通过协调器捕获当前有效应用基线：主题应用保留已活动设置，设置应用保留已活动主题；没有活动配置时才使用恢复值或默认值。确认亮度与电源意图独立捕获，两种表单均不覆盖它们。

主题与设置分别保留表单修订高水位，发送管线由协调器分配独立递增修订；帧号和管线修订不会冒充表单修订。`CoordinatorFrameGuard` 校验设备、会话代次、操作标识及候选／活动管线修订，并将自动恢复映射回原受理操作。较新控制操作受理期间不能开始旧活动刷新。活动产帧必须使用 ActiveProfile.PipelineRevision 构造 FrameContext。

渲染使用冻结内容／设置、当前设备物理尺寸／帧限额、操作上下文及独立新帧号；返回帧须匹配请求，再次核对当前操作后提交受保护首帧。完整 JPEG 校验仍在发送执行者中完成。候选准备失败不写活动／恢复配置；首帧发送失败、部分写或未知不提交活动配置，不声称旧画面已还原。

USB 完整收据交给 `DeviceCoordinator` 的可靠单槽提交消息。协调器循环先处理失效，再检查同设备／代次／操作／管线修订、未取消、已捕获主题和设置、实际收据字段和当前 Ready／Theme／On 状态。只有这些条件成立才更新调度器用户帧率上限并发布独立 `CurrentActiveProfile`，不让工作线程直接写活动配置。候选准备失败不修改帧率。断开时清除当前活动引用；协调器停止或普通提交异常会结束提交调用，不让工作永远等一个丢失的回执。提交成功不代表设备已呈现。

## 保存与本地重试

图片候选使用与渲染器共享的 IAssetStore 预留候选、活动与待保存三类素材租约。取得引用失败发生在发送阶段之前；提交活动后转移活动租约，待保存对象持有独立引用。保存失败／未知保留素材，仅明确保存成功或核实主文件精确提交后释放待保存引用。关闭确认后释放活动引用，未完成保存保持所有者，允许仅本地处理或明确放弃指定候选，见 `asset-reference-baseline.md`。

候选渲染收据核对后，事务先调用调度器 PrepareCandidateAsync。该入口使用发送执行者冻结的能力／固件清单，完整检查 JPEG 结构、全部像素解码、格式／尺寸及分片上限，并在校验前后检查会话守卫。一次最多一个候选校验，不排队、不修改最高管线修订、帧号、待发槽、传输状态或计数，不执行设备 I/O。准备失败／取消可以形成发送前拒绝凭据；首帧只有准备成功且操作仍有效才提交受保护发送。

发送执行者仍执行完整校验与最终帧边界守卫，不能用准备成功跳过发送前验证。目前候选首帧会解码两次，未采用可复用校验凭据；普通刷新解码一次。没有实际性能测量，不能据编译推断首帧时延。排队后的瞬时解码失败仍保守走故障分支，不声称已回滚旧流。

`ApplyForSessionAsync` 返回原组合结果和独立拒绝凭据。只有在首帧提交之前返回的明确 Failure／Cancelled 才产生凭据；未知结果、排队之后的拒绝、部分写、提交失败和保存失败均不产生。凭据构造限制在 Core 内，用例不能靠错误编号猜测设备是否受影响。

会话工作须转交该凭据并执行自身 Drain。协调器仅在同一设备／代次／操作、应用动作、Drain 成功、就绪主题亮屏状态及活动配置均保持原值时保留会话，仍向调用方返回业务 Failure／Cancelled。未知结果或缺少凭据继续走故障路径；过期／断连仍先失效。完成时清除候选基线，避免后续操作读到被拒绝的候选。这不等同回滚已经提交的帧。

活动提交之后独立原子保存恢复配置，返回发送结果、ActiveCommitted、Saved／Failed／Unknown、呈现 NotProvided 和保存重试标识。取得组合结果对象不等于所有阶段成功，页面必须分别读取这些字段。保存失败不撤销已活动候选；重新连接仍读取磁盘旧恢复值。已发送但活动提交被拒绝时，不保存候选，后续设备工作须停流并反馈实际结果。

每个设备服务最多保留一个待保存候选；新的成功活动提交会替换该候选。RetrySave 只读取／写入本地配置，不调用渲染、发送、握手或控制。重试标识、较新活动配置、未知高版本和恢复主题／设置已更新均可拒绝旧候选。仅在恢复文件的亮度／电源值相对应用前发生变化时合并它们；没有发生变化时保留候选已确认意图，避免把旧 Off 值重新写回。素材及其他业务字段不参与这种合并。

Unknown 保存只核实主文件是否精确等于候选；不匹配、备份回退或无法读取时保持未知，不直接重写。普通保存异常记录编号并保留未知候选；已明确失败的保存才可显式重试。应用与本地重试互斥，忙时立即拒绝，不建立无界队列。硬件操作仍须经设备协调器授予，未来亮度／电源／设置保存也须加入同一配置写入所有者，不能绕过它并发覆盖。

## 验证与剩余范围

Core `ThemeApplicationSessionWork` 已实现 IDeviceSessionWork 事务桥接。每次应用冻结主题或设置草稿与指标快照，一个工作只能执行一次；保留 ThemeApplicationAttempt，并转交发送前拒绝凭据。首帧失败／未知或活动提交未确认均不伪造观察成功。USB 完成且活动提交成功后，通过 IApplicationSessionState 核验实际身份／能力／模式／电源／流状态，交由协调器再次验证；本地保存失败不撤销活动提交，页面仍须独立展示保存错误和重试标识。状态核验取消或缺少结果归为未知，不掩盖已经应用。

工作完成后等待同一实际会话所有者 Drain，重复调用共用一个收敛任务，不提前释放操作互斥。工作抛出普通异常返回带编号的未知结果，收敛异常保留未知状态。IApplicationSessionState 的实际只读协议与资源所有者尚未接入，不能用请求值／USB 收据实现观察接口，也不能提供空成功 Drain。此桥接未创建原生会话或调用硬件。

执行 `dotnet build src/UsbDisplayHost.Desktop/UsbDisplayHost.Desktop.csproj -c Release --no-restore`，目标 Desktop Release 及四个生产工程成功，0 警告、0 错误。未运行应用、渲染、文件故障、测试或硬件操作。

已实现应用会话工作；实际状态读取／资源收敛适配器、原生会话、事务前后的活动产帧、指标来源、素材引用租约和 UI 尚未组合；亮度保存、暂停／重连恢复及会话退出收敛仍待完成。发送前拒绝凭据已由工作转交，但排队后的校验拒绝与旧活动续流尚未完成；目前不据此声称旧流已恢复。保存重试需要同一所有者协调其他字段写入，当前编译不能证明未来组合后无竞态。TC-31／TC-32 无行为证据，7.3／7.4／7.5 父项保持未完成。

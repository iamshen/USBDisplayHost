# 诊断传输统计代码基线

关联 REQ-10／FR-10、T-19，任务 8.4。仅有代码与目标 Release 编译证据。

ThemeSessionPipeline.TransferStatus 只读取原 FrameTransferExecutor 的不可变状态快照，不调用设备接口、不新增计数器或订阅。Desktop 唯一会话生命周期在接管门禁内 CaptureTransport，将同一 owner 的设备键、代次、生命周期阶段、原生关闭状态与传输快照组成一个当前会话记录；没有 owner 返回 null，不把协调器 Ready 或发现结果当作已接管管线。

诊断页通过原有可见页 1Hz DispatcherTimer 读取一次快照，隐藏仍停止刷新。页面分为“主机传输”和“设备反馈”：前者显示本会话完整 USB 发送帧数、完整分片确认字节及通道状态；后者目前显示呈现帧数、呈现帧率、设备错误计数未提供，不用主机计数或零替代设备反馈。未知通道错误保留原错误编号。关闭中的 owner 保留统计并标关闭阶段，原生已关闭不显示可发送；引用全部释放后不保留伪在线或跨会话累计。

计数来自实际 SendAsync 写入完成检查。完整分片确认字节包含 AF 包头和已完成分片，不等同 JPEG 净载荷，也不覆盖未确认或短写的实际字节；完整帧数仅在全部分片完整完成后增加。USB 写入完成不能证明设备呈现或刷新率，页面不提供估算 FPS／P95，不进行性能推断。当前 App 未创建实际管线，运行仍显示无已接管会话，不填入模拟计数。

同一 owner 快照还读取 ActiveFrameProducer.Current 和 FrameBoundaryScheduler.FrameRate，不新增计数或循环。页面显示产帧停止／活动刷新故障／回执核实状态、活动刷新已渲染计数（不含应用首帧）、待结算回执、用户／当前帧率上限及末次完整帧发送耗时。上限不是实测 FPS；耗时来自调度器 BeginFrame 至确认发送收据的同一单调时钟，不包括前面的渲染，也不是设备呈现延迟或生产 P95。通道、产帧及发送节奏的业务错误按 ErrorId 去重后持续显示，不因旧 USB 累计计数存在而隐藏产帧循环故障。各组件读数分别来自其不可变快照，可能跨越一次在途更新，不作为原子一致或计数相等的证明。产帧／节奏详情目前仅页面展示，ZIP 中仍只包含已定义的传输摘要。

UI 设备键仅用于本会话归属说明；诊断导出不因此新增序列号、接口路径或原始状态内容。传输摘要已进入 ZIP 的实现见 `diagnostic-transfer-export.md`，实际设备反馈适配器与反馈计数尚未交付。页面读取不修改日志容量、存储写入或素材。

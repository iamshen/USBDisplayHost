关联：REQ-03／FR-03、REQ-08／FR-08、REQ-09／FR-09、T-11／T-13／T-30、任务 5.1／5.2／7.3／9.4。日期：2026-10-08。

Core ThemeSessionPipeline 持有一个物理设备键／代次的应用服务、产帧循环、帧调度器、执行者、传输和实际状态适配器。构造核对应用／产帧使用同一协调器及调度器，调度器使用同一执行者，执行者对应同一传输／设备键／代次；不接受拼接其他会话组件。没有 WPF 或原生句柄依赖。共享渲染器、协调器、存储和指标来源仍由应用层持有。

主题／设置应用均创建一次性冻结工作，经协调器受理实际设备上下文。返回 ThemeSessionApplicationCompletion 同时包含协调器结果和独立应用 Attempt；UI 不能把协调器成功当作本地保存或设备呈现成功。管线仅允许一个应用或保存重试在执行，忙时立即拒绝，没有额外队列；本地重试仍只进入应用服务的本地存储路径。关闭开始后不再受理它们。

CloseAsync 的重复调用共用一个任务。关闭顺序为：通知该代次失效 → 停止产帧并等待其回执 → 等待管线已受理的应用／本地保存 → 停止调度器并等待工作 → 实际状态适配器 Drain → 执行者 Drain → 传输 CancelAndDrain → 传输 Dispose。断连快照不代表已释放句柄。所有收敛使用实际完成结果，不能用已取消用户令牌提前返回。

普通原生关闭异常及非成功收敛返回 Unknown 和错误编号，停止后续资源释放；未知原生关闭不自动重试，也不重新打开替代会话。只有 CloseOutcome 为 Success 时 CanReleaseOwnership 为真。Desktop 生命周期在未满足该条件时保留整个管线的强引用，不能因获得一个已完成的关闭 Task 就丢弃它；实际管线尚未创建／附加，没有运行证据。

此类型负责已组合的应用／产帧关闭，不提供连接、协议恢复、HID 切换、系统关机限时或实际状态读取实现。未来其他设备控制及配置字段写入也须纳入同一会话／配置所有者，不能绕过管线竞争共享资源。

原生关闭任务只执行一次，引用与待保存结果的最终交接是独立步骤。原生关闭成功后释放活动素材引用，未处理的本地保存返回 Failure 并保留待保存租约与整个服务；后续 RetrySave 只允许本地写入，仍禁止新的设备应用。再次 Close 仅核实本地交接，不重新运行已完成的原生关闭，也不自动重试未知原生收敛。只有引用全部交接后 CloseOutcome 才为 Success，CanReleaseOwnership 才为真。

CloseAsync 可携带明确放弃的待保存 RetryId；实际候选不匹配时拒绝丢弃。放弃仅清除待保存元数据与租约，不删除或回滚恢复文件，不声称已发送画面撤销。关闭期间新应用产生的较新待保存候选仍须重新处理。

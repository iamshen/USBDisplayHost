# 主题页真实应用入口代码基线

关联 REQ-04／REQ-08、FR-04／FR-08、D3、T-16／T-30，任务 7.6。仅有代码与目标 Release 编译证据。

App 将同一 DeviceCoordinator、DeviceSessionLifetime 和 MetricSamplingService 注入主题页。现有有界 DeviceSnapshotPresenter 在 UI 呈现阶段更新主题动作可用性，不增加设备订阅或每页会话。当前 App 未创建真实管线，因此实际启动仍为离线保存路径。

同设备／代次的已接管 Active 会话、Ready／Theme／On、已验证能力且未暂停或故障时，主动作显示“应用到设备”；其他状态保留“保存草稿”。已有操作、待保存恢复候选、未知草稿保存、非法输入或退出时拒绝新应用，Core 与唯一所有者仍再次校验。动作区位于独立布局行，结果与按钮分行，按钮使用 WrapPanel。实际紧凑视口、长设备键、高对比度、键盘与读屏器尚未观察。

只有显式点击应用才为本次冻结候选绑定当前设备键／代次；不改写无设备草稿、独立草稿保存修订或后续编辑，不自动恢复或发送。候选图片在整个调用期间持有 Candidate 素材引用。请求读取当前不可变主机指标快照，经过同一会话应用入口。按钮显示“正在应用”，提供取消；取消仍等待原操作返回，不能用 UI 取消代替内核收敛。停止页面时取消并等待应用与保存重试任务，随后释放编辑引用。

结果显示目标设备与冻结修订，分别列出发送、活动提交、恢复配置保存及“呈现反馈未提供”，不宣称设备已显示。应用时的新编辑保留且标明未应用，不将设备恢复配置保存当作离线草稿已保存。首帧或保存失败保留输入和错误编号；已受理调用的意外异常提示结果未确认，不建议直接重发。

“重试保存”绑定原 SaveRetryId，并重新核对当前 PendingSave 标识及忙碌状态，只调用原会话 RetrySaveAsync；原 Core 对未知写入核实主文件，不重发主题。成功保留原发送／活动结果并更新保存状态，不覆盖新编辑。待保存所有者变化时旧按钮不能写入另一候选。

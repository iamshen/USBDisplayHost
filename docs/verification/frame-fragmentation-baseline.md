# 数据面编码与分片实施状态

日期：2026-10-08。关联 REQ-03／FR-03、T-08、TC-05，OpenSpec 4.1。当前依据变更设计与原始参考的字段布局实现编码，不作为数据面契约已冻结或固件已匹配的证据。

## 生产实现

Core FrameFragmentPlan 创建时验证非空帧、固件帧限额及 1MiB 软件上限。传输 T 取 245760、调用方固件限额、主机限额三者最小值，必须大于 11。调用方须从实际已验证契约和适配器获得限额，不能用编码器成功证明设备能力。

游标只保存长度与偏移，不生成整个分片列表。剩余不超过 T-11 时生成唯一 0x69／11 字节尾片；否则使用 0x68／8 字节头，payload=min(T-8, remaining-1)，保留至少一字节给尾片。AF 前缀、src_offset 和本片 payload 长度均明确编码，后两者为 24 位大端；尾片 pixel_offset 的三字节清零。

调用方提供一块可复用缓冲，成功后返回实际包长；长度不一致、小缓冲或重复完成调用返回错误，不推进偏移，不填充未定义字节。游标只有单发送者使用，帧内容必须在所有片期间保持不变；上一片原生完成前不能覆写缓冲。原生完成及内核取消资源所有权仍由发送／Windows 适配器落实。

AfCommandEncoder 生成 AF 20 command value 四字节，仅接受已列出的颜色／宽高／背光／AUTORLX／MJPEG／BLANK_MODE 命令。背光范围 0～100，AUTORLX／MJPEG 为 0／1；BLANK_MODE 当前仅提供亮屏握手值 1，不用此入口实现纯熄屏或 POWERDOWN。颜色格式值仍须来自冻结契约，编码器不猜测设备支持格式、不试发 0x30+ 扩展命令。

字段依据：[原始参考 B5／第 6 节](../参考资料/USB_副屏协议与局部刷新原理.md) 及 [变更设计 D4](../../openspec/changes/build-usb-display-host-v1/design.md)。原始参考保持未修改；其接收行为陈述未在本项目核实。

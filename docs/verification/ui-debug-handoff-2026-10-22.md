# 另一台电脑的 UI 调试提示词

将以下正文复制到该电脑的 USBDisplayHost 仓库会话中。

---

请继续 USBDisplayHost 的真实 WPF 界面调试，直接检查、修复并复核发现的问题。

先读取 AGENTS.md、HANDOFF.MD、README.md、docs/06_UI设计规范.md 和 docs/verification/ui-simplification-2026-10-22.md。检查工作区差异，保留本机已有改动。识别指向 https://github.com/iamshen/USBDisplayHost.git 的远程，拉取 main 的最新提交；工作区干净且可快进时使用快进合并，有未提交改动或分叉时先保护再合并，不覆盖、不强推。记录实际调试的提交号。

当前版本已整合两台电脑的修改：本机界面精简和离线安装打包，以及远程的 DPI／托盘注册、导航选中态、亮度初值、日志对齐、响应式布局和时钟／仪表盘渲染修复。合并版 Release 构建通过，但尚未完成真实窗口验收；旧截图不能作为本轮结果。

设计目标是简洁、克制、留白，让布局和视觉层级解释关系。删除重复上下文、装饰图标和无用途的卡片；次要细节按需展开。保留必要标签、自动化名称、键盘焦点、预览来源、当前设备归属、禁用原因和异常恢复入口。重要状态同时用文字或形状表达，不仅依赖颜色。沿用现有资源、字体和间距，只修复发现的问题，不扩展无关重设计。

我授权本轮仅界面运行检查、截图及必要的 UI 修复与构建；不授权新增或执行单元测试、自动化测试代码，不连接或控制真实设备，不执行安装、卸载或驱动操作。使用 --ui-only；它仍会使用真实本地配置和日志。应用设置优先用预览和撤销验证，不改写自启注册或设备策略。DPI、高对比度及文字缩放可临时调整，先记录原值，完成后恢复。

从仓库根目录执行 ./build.ps1 -Action Build。先核实当前是否有安装版或旧构建驻留：单实例锁可能让新启动只唤起旧窗口，不得把旧版本当成本轮结果。已有实例若含未确认编辑或设备会话，不要强制终止，应通过正常退出流程处理。确认后运行 dotnet run --project src/UsbDisplayHost.Desktop -c Release --no-build -- --ui-only，并核对进程路径与本次构建一致。

实际点击、编辑、滚动并检查以下内容：

1. 五个页面：设备、主题、设备设置、诊断、应用设置。覆盖顶部、侧边和紧凑菜单导航，反复点击当前页及切换页面，确认选中态、焦点和编辑内容正确。
2. 常规与窄窗口：1180×820、1180×760、800×600、640×400 DIP。记录实际窗口／客户区尺寸及 DPI，不能把截图像素直接当作 DIP；检查页头、字段、预览、滚动区域和底栏无重叠、截断或不可达操作。
3. 主题页：图片、时钟、仪表盘三个选项，图片导入与适配、颜色输入及色板、日期／24 小时制、指标开关、撤销和恢复默认。确认短窗口预览比例、来源说明和底栏；无数据指标不得显示虚构数值。
4. 设备设置与应用设置：设备身份和未连接原因、参数范围及控件名称、双列转单列、导航布局预览与撤销。--ui-only 中设备控制保持禁用；不要为了截图解除业务门禁。
5. 诊断：表头与事件行对齐，级别文字和颜色一致，错误编号完整可读，空状态和滚动正常。检查本次启动及交互日志有无新增异常。
6. 键盘 Tab／Shift+Tab、选项方向键、焦点、可访问名称、高对比度；条件允许时检查 100%／125%／150%／200% 缩放和混合 DPI。不能执行的项目明确标为未验证。

每个问题先记录复现步骤和实际截图，定位根因后做最小修改，再重新构建、运行并复核受影响页面。截图必须来自当前构建的真实 WPF 窗口，保存到 docs/verification 下本轮独立目录，记录提交号、页面、窗口／客户区尺寸、DPI、文字缩放及数据来源。无法在 --ui-only 中出现的连接、硬件错误和恢复状态保持未验证，不制造假状态作为验收。

最终交付问题与修复清单、实际截图、执行命令和结果、未覆盖项；更新验证记录与必要的 HANDOFF.MD 经验。不提交或推送代码，等待我另行授权。

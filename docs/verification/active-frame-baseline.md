# 活动产帧实施记录

关联：REQ-03／FR-03、REQ-04／FR-04、REQ-09／FR-09、T-11／T-12／T-30、任务 5.2／7.3。日期：2026-10-08。

Core ActiveFrameProducer 每个物理会话一个循环。只读取协调器 CurrentActiveProfile；时钟／仪表盘每秒捕获最新活动主题、设置、物理尺寸、时间和最多 64 项指标快照，渲染前后核对设备／代次／操作／管线修订。静态图片不周期重发，内容或方向／画质变化由应用事务的受保护首帧更新。PeriodicTimer 合并错过的时刻，不累积补发请求；实际渲染过慢时更新频率可能低于 1Hz，不声明达标。

首帧与活动刷新共用 FrameBoundaryScheduler 的单调帧号分配器；准备失败可留下序号空隙，不能重复使用旧帧号。帧号达到限额或会话停止时拒绝分配。产帧请求使用 ActiveProfile.PipelineRevision，不使用表单修订。

一次只等待一个渲染请求完成，不使用无界后台任务。发送仍交给调度器的一个在途和一个最新待发槽；新普通帧替换待发帧后，旧回执立即收集。循环保留至多两个未完成发送回执，提交／收集期间最多三个任务引用；违反这一界限停止产帧并保留错误。较新活动提交或控制操作到来时，旧渲染收据不排队，不中途截断已经开始的 USB 帧。

调度器停流、暂停、恢复未确认或发送节奏要求恢复时不生成新帧。普通渲染故障暂停同一活动修订；未知发送回执、缺少结果或收据不匹配锁存整个产帧器的回执恢复要求，不能靠新活动修订自动解除。显式 ResumeAfterRecovery 仅在实际发送通道、原设备／代次及当前活动上下文允许时清除产帧故障，不执行设备恢复或重放失败帧。一般发送失败保留独立错误，是否允许下一帧由通道真实恢复状态决定。新活动配置可以越过旧修订的渲染故障，不能绕过回执恢复要求或发送通道故障。

产帧器创建时冻结调度器所属设备键／会话代次；协调器选中其他设备或进入新代次时，不读取其指标、分配帧号或渲染。每个待回执保留原 FrameContext、帧号和 JPEG 长度，不保留额外 JPEG 副本。成功收据必须精确匹配原帧，错误状态携带原管线修订；旧活动普通失败不覆盖新活动错误，新活动完整成功可以清除此前普通发送错误。回执按提交顺序收集，避免先处理较新成功再被较旧失败覆盖；未知结果仍锁存所属物理产帧器，不能冒充对新活动的设备观察。

Dispose 的多个调用共用一个停止任务；取消自身渲染／待发请求，等待渲染结束及已有发送回执，不释放共享渲染器、调度器、协调器或原生会话。普通循环与回执异常记录错误编号，未完成原生收敛不能据此报告已安全关闭。实际会话所有者必须等待产帧停止，再按既有边界收敛／释放共享资源。

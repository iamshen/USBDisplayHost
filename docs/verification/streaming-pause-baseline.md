# 完整帧边界暂停／恢复代码基线

关联：T-11／T-16／T-30，任务 5.2、7.5、8.2。

ThemeSessionPipeline.SetStreamingAsync 使用现有会话操作门禁，按实际设备键、会话代次和活动草稿修订提交 Pause／Resume。它与应用、本地保存和关闭共用在途任务槽；正在关闭或已有操作时不受理。协调器再次核对当前模式、电源、推流状态及能力，不直接修改快照或编辑草稿。

StreamingSessionWork 在同一个 FrameBoundaryScheduler 中排队，已有完整帧继续完成，边界工作没有数据写入、亮度、电源或模式命令。边界前取消不执行观察；授予边界后实际观察和收敛继续完成，不把用户取消解释为没有改变通道。观察器返回的实际身份、主题模式、On 电源、驱动和能力必须匹配原会话，期间代次失效拒绝发布。随后只将主机拥有的 Streaming 字段改为 Paused／Running，设备事实保留实际观察结果；不能由此宣称设备呈现确认。

暂停保持调度器停止接收帧并清除尚未发送的待发槽，不截断在途帧；活动配置和恢复配置不替换。恢复要求已有活动配置属于同一设备和代次、帧执行器 Ready、无未知 I/O 或帧率恢复要求。Resume 不清理 parser、不打开设备、不应用草稿、不重放首帧、不保存配置。成功后动态主题沿用原活动配置按既有周期继续产帧；静态主题保持既有画面。尚无活动配置时，恢复仅开放通道，产帧器仍无配置可生成画面，之后允许显式应用；不能将其变成自动加载恢复文件或草稿。

实际观察与收敛依赖原 IApplicationSessionState。边界与协调器共用同一次观察收敛任务，未授予边界时不启动新的控制 I/O 清理。错误或未知结果不伪造 Running；协调器按已有规则进入故障并保留未确认所有者，普通异常返回原因、动作及错误编号。管线关闭等待已受理的推流操作。

观察器 DrainAsync 的同步调用异常和异步异常均在缓存收敛任务内转换为 Unknown。帧调度器与协调器读取同一结果，不能因为同步异常发生在任务赋值之前而让协调器误读成“从未开始、无需收敛”。

Desktop DeviceSessionLifetime 已提供显式设备键／代次的推流入口，要求原会话 Active、没有构建／关闭／在途操作，不允许用旧页面上下文控制新设备。设备页提供暂停／恢复按钮，按 Core OperationAvailability、实际发送通道和未知收据锁存决定可用性；点击再次核对并冻结目标。没有实际管线时按钮不可用，结果始终注明原目标，失败与错误编号常驻。状态订阅和可见页既有 1Hz 刷新更新门禁，不创建新的设备循环。页面停止取消并等待已受理命令，管线关闭仍等待实际操作收敛。

恢复前管线拒绝活动未知收据。有活动配置时，协调器成功发布原活动 Running 后，再核对产帧器是否能恢复，并解除同配置的已知渲染失败限制；恢复拒绝则使原代次失效，返回 Unknown，不发布页面成功。无活动配置时不调用要求已有配置的产帧恢复，不构成发送／呈现或内容提交。普通异常通过原会话和页面错误边界保留会话及诊断，不关闭窗口。

TrayService 由 App 注入同一个 DevicesPageViewModel，暂停／恢复菜单直接绑定设备页已有命令实例。窗口和托盘共享 IsChangingStreaming、实际所有者及 Core 门禁，没有独立管线、操作任务或设备状态副本。隐藏时打开菜单先 RefreshStreamingActions，避免依赖暂停呈现的页面快照；命令点击仍读取当前设备键／代次并二次校验。模式切换暂未接入，保持明确不可用。

推流失败通过唯一 PropertyChanged 订阅将原错误带到工作区并唤起窗口，结果保留在设备页；成功不自动弹窗。呈现或唤起的普通异常单独记录，错误呈现失败不递归重放动作。TrayService.Dispose 在释放原生图标前解除该订阅；真正操作由设备页 StopAsync 等待，托盘不另行取消或重发原操作。

# 最新帧与完整帧边界调度实施记录

关联：REQ-03／FR-03、REQ-09／FR-09、T-11、任务 5.2、TC-16／TC-32。日期：2026-10-08。

## 生产代码

Core 的 `FrameBoundaryScheduler` 组合整帧执行者，一个后台执行循环串行处理全部工作。上限为一个在途工作、一个待发帧及八条控制操作；唤醒信号最多一个，不为每个提交创建后台任务。输入帧长度最多 1MiB，固定活动尺寸 1920×1080，设备键、代次、操作号、修订与帧号必须有效。完整 JPEG 及固件检查仍由发送执行者执行。

普通帧替换尚未发送的普通帧，旧调用返回 Cancelled，并独立累计主机替换数量。待发主题应用首帧不能被普通刷新或另一首帧替换；它占用同一个待发槽，没有额外无限候选队列。已受理修订及同修订帧号单调增加，迟到旧帧／重复帧号不能覆盖最新内容；失败或取消后的重新渲染须提供新帧号，不能复用已受理编号。

新提交不取消在途发送，帧内不会执行控制。完整帧结束且 I/O 收敛后，控制按受理顺序优先取得帧边界，再执行待发帧。每项控制在执行前重新核对操作上下文，构造和入队不得执行 I/O；执行成功、失败、异常或取消后均由所属工作负责 Drain。已取消／已过期的未执行控制不调用硬件。控制工作保留冻结上下文，设备协调器仍须过滤旧代次完成。

开始控制时暂停新帧受理。只有 Success、明确的 `AllowsFrameStreaming` 和再次核对当前控制操作同时满足才允许继续推流；工作须在返回成功前发布核实的观察状态。接口默认不允许继续推流，熄屏／切模式／暂停不应覆盖该默认值。恢复工作明确授权继续，但后续发送仍受 Theme／On／修订守卫约束。控制失败或结果未知则清除尚未发送的帧并保持停流；没有自动恢复旧状态。

帧或控制 Drain 非 Success 时，调度器停止并拒绝全部新工作，保存错误编号及未知控制的强所有者。未执行的待处理工作明确结束，不把别人的未知 I/O 结果当作它已经执行。正常退出清除待处理工作并等待在途帧／控制实际结束，不为了退出截断完整帧；后台退出后仅释放自身同步资源。无法确认内核收敛时 Dispose 返回异常，所属会话必须保留调度器与执行者，不能报告资源释放成功。

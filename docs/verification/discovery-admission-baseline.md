# 发现代次与选择受理代码基线

关联 REQ-01／FR-01、D2／D3、T-09，任务 4.2。

Core 新增 DeviceSelectionAdmission 与 IDeviceSelectionValidity。协调器选择入口要求选择及其有效性凭据，排队时不把确认结果当成永久有效事实。实际受理前检查凭据，发布 Discovered 后再次检查；已经变化则失效并返回失败，不返回成功选择。普通核验异常带错误编号返回，不使协调器循环退出。有效性接口只允许内存核对，不执行 I/O 或回调协调器。

Windows 凭据绑定原 DeviceSelection 对象、发现列表版本和所属发现生命周期，不接受替换的选择对象。列表版本、通知代次、已消费代次一致，且未关闭／订阅失败时才有效。界面候选确认和 SelectedDevice／SelectedAdmission getter 均使用同一门禁；隐藏窗口尚未呈现更新也不能向业务返回已过期选择。

通知回调先保留移除路径／归属未知标记，再推进变化代次并发出重扫信号。通知消费者在一批记录消费前捕获代次，先交付移除记录，最后发出带该代次的重扫标记。发现生命周期收到标记才开放初次枚举，标记消费与实际通知代次未追平时不发布可选择成功列表，防止已有重要移除还未接续时受理新选择。期间又到达通知时保持拒绝，后续重扫收敛最新列表。

成功列表同时核对枚举前后通知代次与已消费代次。凭据核验为当前内存状态的线性化观察，不保证之后不会再次拔插；正式连接仍必须在打开及交付前核实当前凭据、实际描述符和资源所有权，新的通知继续由已有代次失效链处理。

尚未在 App 启用真实发现或受理正式连接，模式切换后的接口集合、打开／连接用例组合及实际快速重插证据未完成。不能把凭据有效、Discovered 或编译通过当作设备 Ready。

仅运行目标 Release 构建，四个生产工程 0 警告、0 错误。未创建或运行测试，未执行通知、选择、原生调用或窗口。4.2 父项及真实设备验收保持未完成。

# 诊断导出未知提交核实代码基线

关联 REQ-10／FR-10、T-19，任务 8.4。仅有代码及目标 Release 编译证据。

DiagnosticExportService 对导出、核实、放弃共用非排队受理门禁。已有操作返回明确 Failure，不创建第二个后台导出；已有 PendingDiagnosticExport 时拒绝新导出覆盖确认记录。完整 ZIP 写入、flush 和输出关闭后，流式计算临时文件 SHA-256 与长度，再在 File.Move 提交前冻结 VerificationId、目标路径、哈希和原导出摘要。提交前取消保持原目标；提交阶段异常／取消保留记录并返回 Unknown，不能断言目标未变化。

VerifyAsync 必须匹配原 VerificationId，只打开原目标只读句柄，不重建 ZIP、不发送或读取设备、不修改目标。长度或完整 SHA-256 不匹配时保留记录；读取、取消或关闭异常也不解除保护。只有匹配且读取句柄关闭后，才清除确认记录并返回原导出摘要。核实是与本次已准备 ZIP 的字节一致性确认，不是软件包签名或设备验收，也不是对目标历史内容的恢复。

正常导出在 File.Move 返回后也复用该只读核实：实际目标 ZIP 的长度与完整 SHA-256 匹配且句柄关闭，才写 Completed 并返回 Success；不把临时文件哈希或 Move 返回值单独当作目标字节证据。目标不匹配、读取或关闭未确认返回 Unknown 并保留本次记录。提交后的核实不使用用户取消令牌，等待此次操作实际结算，避免将已经改变目标的提交描述为取消且原文件保留；提交前的取消边界不变。

手动 VerifyAsync 的文件打开、长度读取及流式哈希均从后台任务开始，UI 线程只执行受理门禁；核实期间继续占有同一操作门禁，其他导出或放弃不能覆盖记录。后台任务不会被用户令牌提前跳过后报告已结算，令牌仅由真实读取链处理；取消仍保留原标识。增加目标文件的一次完整只读哈希，没有新增设备操作或无限重试；实际耗时尚未测量。

Desktop 已增加“核实导出”“取消核实”“放弃导出核实”，待确认时禁用重新导出。放弃核实必须使用当前标识，只清除内存元数据，不删除目标、不回滚已经发生的覆盖、不报告原导出成功。页面停止取消并等待核实任务。错误仍通过原错误编号展示；没有自动覆盖、删除目标或无限重试。

Pending 记录仅由应用进程内 exporter 持有，目标路径和哈希不写入导出摘要或日志白名单；不提供跨重启恢复或退出前的确认记录持久化保证。异常提交后原临时文件按既有临时清理责任收敛，核实依据目标完整哈希，不依赖临时文件继续存在。实际文件系统行为、文件占用、异常提交、核实和取消尚未运行验证。

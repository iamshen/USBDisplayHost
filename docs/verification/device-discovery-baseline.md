# Windows 设备发现桥接代码基线

关联 REQ-01／FR-01、D2／D3、T-09、任务 4.2。接口通知与路径来源见 `device-interface-monitor-baseline.md`。这里记录生产桥接与编译范围，不是身份探测或真实连接验收。

## 发现链

`WindowsDeviceDiscovery` 实现 Core `IDeviceDiscovery`，拥有一个路径监视器与一个 `IDeviceInterfaceIdentityProbe`。调用方先实际启动变化流消费，再发起枚举；仅取得 IAsyncEnumerable 对象不表示订阅已经开始。未订阅或关闭后拒绝枚举。

枚举与关闭使用同一串行门，最多一个枚举批次、一个实际身份探测。每项探测携带用户／生命周期合并取消令牌，探测返回或抛出普通异常后，均先以不可取消收敛查询确认原生资源完成，再处理该项结果。取消不是完成证明；收敛失败／未知或探测自身 Unknown 会保留错误与探测所有者，后续枚举不能重复探测。

探测接口成功 null 只能表示明确核实为非目标接口，访问失败或没有可信身份不能用 null 跳过。成功身份核对实际路径、非零 VID、有效序列号、容器字段和有界位置描述；不从设备路径解析 VID/PID 或拼接序列号，也不声明驱动、模式或能力已验证。输出全部成功列表或整体失败，不能用部分发现成功掩盖某个目标身份探测失败。

路径枚举标记变化、探测前后变化代次不一致、订阅终止或关闭开始，均拒绝发布旧列表。末尾再次检查取消与代次；返回后仍可能发生新的热拔插，后续明确选择／连接必须继续使用选择解析器和会话守卫，不能把一次列表当成长期在线证明。

重复序列号、同容器接口聚合及歧义仍交给 Core DeviceSelectionResolver 在明确选择时拒绝，发现链不自动选第一台设备。通知保持容量一 RescanRequired 语义，没有制造精确到达／移除路径；离线优先仍需上层重扫及当前会话失效接入。

关闭先拒绝新批次并发出生命周期取消，等待在途枚举退出，再核实探测器收敛、释放探测器、注销监视器。普通关闭异常或未知收敛保留整个所有者及错误，不能将 Dispose 无异常当作原生收敛证据。Close 共享同一结果，不自动重开探测或监视。

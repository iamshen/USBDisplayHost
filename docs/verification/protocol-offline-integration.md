# AD102 V2 上位机协议接入

更新：2026-10-12。范围：上位机源码实现与目标编译；设备联调等待设备可用后单独开展。关联 REQ-01～03、REQ-06、REQ-09、REQ-11～13，FR-01～03、FR-06、FR-09、FR-11～13，T-07～T-10、T-21；原有运行及硬件验收任务保持未完成。

## 固件与字段基线

只读依据为相邻 `USB_DISPLAY_AD102` 仓库提交 `b887bc192d1ef45ebe40662aecfbcddfbb6e516d`，包括 `usb_display_ad102/上位机实现文档.md`、V2 实施记录及 `vendor/usb_camera/usb_v2_hid.c`、`usb_display.c`、`usb_mode_switch.c` 和 gadget Display 实现。未修改、构建或运行固件。

| 通道 | 当前实现与主机处理 |
|---|---|
| 身份 | VID A108，THEME PID ADA0，SCREEN PID AD11；读实际序列号、容器和接口身份。同序列号重枚举后重新建立会话。bcdDevice 不作为协议版本。 |
| HID | usage page FF00、usage 1；Input 1、Output 2、Feature 3，均 64 字节，含 Report ID；Feature 版本 2.0、能力位 0x15F。 |
| 状态 | Input 字节 1 是显示使能／AUTORLX／切换标志，2 是原始背光，12／13 是当前／目标模式，14 是维护忙，15 是错误，16～18 是命令／结果／token，20～23 是小端能力位，24／25 是 Display 命令／结果，26～27 是小端计数，28 是旋转。 |
| 状态探测 | 固件没有周期 Input 或独立查询命令。主机串行发送 Output `02 00 00 FF` 加零填充，利用未知命令返回当前状态的实际源码行为；通常结果 Unsupported，token 与旧命令碰撞时可为 Invalid。这不是新增固件命令，会改变最近命令诊断字段。超时后不再沿用该会话的状态关联。 |
| 模式 | HID 31，参数 0=THEME、1=SCREEN，与内部模式枚举相反。模式 token 使用 1～254，255 留给状态探测；ACK 只证明受理，目标 PID、Feature／Input 与同一物理设备重新连接才完成主机协议切换。 |
| Display 打开 | 从已安装 WinUSB 驱动注册的 DeviceInterfaceGUIDs 枚举，读取实际接口和唯一 bulk OUT。限定 class FF／subclass FF，排除 FF／00 Maintenance；不虚构 GUID、不固定 MI 或端点，不安装驱动。 |
| EP0 | `C1/01` 读 1 字节状态，ready 掩码 0x18；`C1/02` 读 128 字节 EDID、DTD 偏移 54；`C1/04` 读 1 字节背光。wIndex 取实际 Display 接口号。 |
| AF 命令 | 补齐 `AF 20 30 00` 清理、34 旋转 0～3、36 电源 0／1、38 heartbeat 值 0 的编码；清理、电源、旋转通过 Input 最近 Display 命令／结果／计数增量确认。背光 05 通过 HID 与 EP0 交叉读回。heartbeat 编码可用，未加入额外定时发送。 |
| JPEG | 1920×1080，baseline C0／8 bit，Y 分量采样 2×2、2×1 或 1×1，Cb／Cr 1×1；1 MiB 帧上限，分片受实际传输限制约束。XRGB888 初始化值 2。主机执行内容旋转，固件旋转恢复为 0。 |

HID 30 是整机复位，不用于半帧恢复；EP0 03 也有复位副作用，不作为查询调用。未开放维护或升级命令。设备指标占位零值不作为真实温度、FPS 或呈现证据。

## 已接入的软件路径

- 设备页检测、显式选择与连接已经组合原生发现、HID 控制、主题 WinUSB 打开和既有主题管线；页面及托盘共用模式命令。状态展示区分 `SourceMatched` 源码基线与 `Verified` 实机证据。
- 主题连接执行状态读取、接收清理、初始化与当前内容首帧；帧失败恢复复用原有一次恢复守卫。清理会关闭固件显示使能，因此恢复适配器在返回清理收据之前重新建立初始化及电源意图并读回确认。
- 亮度、熄屏、唤醒经过唯一协调器与帧边界执行；熄屏保持主题连接，唤醒恢复接收状态和当前内容。USB 写完成不等同于状态确认或屏幕呈现。
- 控制成功与本地保存分开处理。控制字段在共同存储边界内合并到最新恢复配置，避免覆盖主题内容；失败保留候选和素材引用，重试只写本地，未知写入先核实主文件。退出可处理待保存结果。
- 模式切换先收敛并关闭主题数据面，再发送一次 HID 请求。释放旧会话后，在 8 秒目标等待预算内重新检测同序列号目标接口，随后做一次超时枚举与状态核实；断线恢复独立使用 30 秒预算。丢 ACK 不盲目重发或反向补偿。
- 已选择设备的拔插与系统唤醒接入关闭旧会话和重新发现；恢复不自动发送模式切换。协议操作支持取消，退出等待已有操作与原生资源收敛。
- 显式退出已接入已保存的“退出切副屏”意图处理。后续同日补齐自动策略的设置门禁、启动发现与唯一设备连接、首次切出提示和状态查询，详见 [离线工作区补齐](offline-workspace-completion-2026-10-12.md)；默认不切模式，Off 不自动唤醒，运行行为仍待验证。

## 当前固件边界

`usb_mode_switch.c` 在切换时无条件设置电源为 On，主机无法保证跨模式全过程保持 Off。因此 Off 时拒绝模式切换并说明原因；纯主题熄屏／唤醒通过 Display 36 实现。SCREEN 缺少主题 Display 通道，不开放亮度／电源命令。SCREEN 的 HID 模式确认不代表 Windows 桌面显示路径已就绪。

源码匹配仅代表主机按该版本字段实现，不能证明设备烧录了该提交。安装驱动、实际枚举路径、固件镜像、WPF 窗口交互、JPEG 接收与呈现、重枚举时序、睡眠恢复和稳定性仍待联调；与该源码不同的固件需重新核对契约。

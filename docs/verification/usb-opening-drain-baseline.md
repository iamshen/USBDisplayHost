# USB 打开与收敛协作代码基线

关联 REQ-01、D3、T-10，任务 4.3／9.4。

WinUsbDisplayTransport 使用单一逻辑打开取消源，链接调用方取消并持有至下一次合法打开或确认释放。CancelAndDrainAsync 在传输门内受理一个收敛任务，重复并发调用共享该任务，期间拒绝新的打开、写入及 EP0 控制。

尚在打开时先请求内部取消，但不以调用方取消丢弃正在执行的工厂任务。即使取消回调普通异常，也先等待打开结算。成功打开的会话由适配器接管并继续取消／收敛实际请求；失败／取消且确认工厂清理完成时才允许返回成功收敛，Unknown 或工厂释放未知保留错误和所有者。普通等待／取消异常转换为带错误编号的 Unknown。

收敛未知时禁止业务 I/O 和重复打开；之后对同一所有者的显式 drain 仍可确认原内核请求，不重发设备命令，不替换会话或重放原生 Free。只有实际收敛成功才清除业务 I/O 门禁。收敛成功仅证明打开任务及原生请求已经结束，仍存活的会话文件／USB 句柄由 Dispose 释放，不能当作全部资源已释放。

Dispose 先设置关闭门禁并等待同一收敛链，确认后再关闭实际会话和取消源。打开受理阶段的普通异常返回 Failure；已经进入原生工作后的普通异常沿用未知收敛处理。释放任务保持单次执行，未知关闭继续保留所有者。

同步驱动打开／初始化／描述符调用无法靠取消 Token 中断，收敛继续等待真实任务，没有保证驱动卡住时有界退出。实际 App 连接、关闭与驱动行为证据仍未完成。

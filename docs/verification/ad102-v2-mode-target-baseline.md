# AD102 V2 重枚举目标核验

日期：2026-10-09。关联 REQ-11～REQ-13／FR-11～FR-13、T-22、T-23、TC-20～TC-23，任务 11.3、11.4。

Prepare 在模式请求中冻结 On／Off 电源意图，未知意图被拒绝。模式记录新增 VerifyTarget，仅在原记录已经 Retire、原写入已完整确认、仍持有原请求且尚未结算目标时受理。丢失 ACK 不阻止真实目标核验；原生写入未确认时不能用目标出现替代 I/O 收敛。成功只交付核实后的 DeviceObservation，保留旧请求与 token 历史，不关闭原生资源或授权重建所有者。

目标证据携带新的 OperationContext、DeviceSelectionAdmission、当前 Feature、DeviceObservation，以及主题初始化／已完成首帧。要求设备键、原操作号与修订完全相同，目标代次严格大于原 HID 代次；进入和交付前分别核对内存中的发现与当前上下文凭据。身份必须来自当前选择、序列号能解析到原设备键；实际模式、当前 Feature 的 current／target 模式都匹配目标，维护不能占用，驱动和兼容能力必须已核实，实际电源必须与冻结意图一致。Feature 的能力声明本身不授予 Verified 能力。

副屏必须提供已核实的系统显示路径并保持主题推流停止，不能附带主题初始化或首帧；只有目标 PID 出现不能通过。主题尺寸为 1920×1080。亮屏主题要求同一新会话的已核实初始化和完成亮屏序列，首帧来自生产 JPEG 验证与发送管线的 CompletedHostFrame；帧／收据的设备、代次、操作、修订、活动用途、帧号、长度、分片数量、总包字节数和完成时刻必须一致。USB 首帧收据不等于设备已经呈现。

熄屏主题不要求执行数据面初始化或发送首帧，以避免为验收强制亮屏；必须实际 Off 且停止推流。如果提供了初始化收据，它须属于同一新上下文并为 Off、零控制命令、未执行亮屏序列。任何首帧或亮屏初始化证据均返回 Unknown。该规则与现有 ThemeDataPlaneInitializer 的 Off 跳过／只读探测路径一致。

核验器是 Core 内部纯规则，不持有原生句柄；发现有效性及当前上下文委托只读内存，不在记录锁中调用。委托异常转为诊断编号和 Unknown，不能清除请求、重发切换或宣称回滚。同一目标仅结算一次，实际使用者仍须经所有者关闭／收敛与协调器当前上下文门禁交付状态，不能直接把该方法当作完整模式切换用例。
